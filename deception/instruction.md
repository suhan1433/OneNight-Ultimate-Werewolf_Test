# 역할
너는 시니어 풀스택 엔지니어 겸 모바일 게임 UX 디자이너다. 아래 명세대로 "4~12인 실시간 멀티플레이 추리·블러핑 웹게임(PWA, 모바일 퍼스트)"을 끝까지 구현하라.
- 질문하지 말고, 모호한 부분은 합리적으로 가정한 뒤 README의 "가정" 섹션에 기록한다.
- 작업명: "네온 사건파일(가칭)". UI 기본 언어는 한국어이고 i18n 구조는 갖춘다(en 추가 가능).

# 0. 콘텐츠·IP 원칙
- 게임 규칙(메커닉)은 1장 그대로 구현한다.
- 원작의 카드 문구, 타일 문구, 일러스트, 로고, 제목은 쓰지 않는다. 모든 텍스트와 그래픽은 오리지널로 만든다. 세계관은 "네온 항구도시 느와르"로 한다.
- 비상업 프로토타입을 전제한다. README에 "상업 출시 시 원작 퍼블리셔 라이선스 검토 필요"를 한 줄 적는다.

# 1. 게임 규칙 명세 (구현의 정답 기준, 공식 룰북 확인본을 요약)

## 1.1 개요와 승패
- 한 명이 범인인 사건을 수사하는 추리/블러핑 게임이다. 플레이 시간은 약 20분이다.
- 범인은 자기 앞에 놓인 카드 중 "핵심 증거(단서 카드 1장)"와 "범행 수단(수단 카드 1장)"을 정답으로 몰래 고른다.
- 수사팀(법의학자 + 수사관 + 목격자)이 이기는 조건: 법의학자를 제외한 누군가가 정답 두 장을 모두 맞게 지목한다.
- 범인팀(범인 + 공범)이 이기는 조건: 모든 플레이어가 해결 기회를 소진한다(오답을 냈거나, 마지막 발표까지 시도하지 않았다).
- 반전: 목격자가 있는 게임에서 정답이 나와도, 범인이 목격자를 정확히 지목하면 범인팀이 역전승한다.

## 1.2 인원과 역할
- 4~5인: 범인 1, 법의학자 1, 나머지는 수사관이다(공범과 목격자는 없다).
- 6~12인: 범인 1, 법의학자 1, 공범(선택), 목격자(선택, 공범이 켜졌을 때만), 나머지는 수사관이다.
- 기본값은 6~7인이면 공범 ON, 8인 이상이면 공범과 목격자 ON이다. 방장이 바꿀 수 있다.

| 역할 | 아는 정보 | 특이사항 |
|---|---|---|
| 법의학자 | 정답 두 장, 범인, 공범 | 신분이 공개된다. 게임 마스터다. 자기 카드는 버리고 장면 타일로 플레이한다. 단서 전달은 "총알 배치"와 "해결 시도에 대한 예/아니오 응답" 두 가지뿐이다. |
| 범인 | 정답 두 장, (있으면) 공범 | 자기 카드 중에서 정답을 고른다. |
| 공범 | 범인, 정답 두 장 | 범인팀이다. |
| 목격자 | 범인과 공범 두 명의 이름 | 누가 범인이고 누가 공범인지, 수법이 무엇인지는 모른다. 수사팀이다. |
| 수사관 | 없음 | 수사팀이다. 범인(과 공범)이 수사관 사이에 섞여 있다. |

## 1.3 세팅
- 법의학자를 제외한 모든 플레이어에게 단서 카드 4장과 수단 카드 4장을 나눠 주고, 모두가 볼 수 있게 공개한다.
- 난이도 옵션은 3장씩(쉬움), 4장씩(기본), 5장씩(어려움)이다.
- 카드 그림은 참고용이고 텍스트가 기준이다.
- 법의학자를 제외한 모든 플레이어는 "해결 기회 배지" 1개를 받는다.

## 1.4 범행 단계(밤)
1. 전원이 눈을 감는다.
2. 범인(과 공범)만 눈을 뜬다.
3. 범인이 자기 단서 1장과 수단 1장을 정답으로 지정하고, 법의학자가 이를 확인한다.
4. 범인(과 공범)이 눈을 감는다.
5. (목격자가 있을 때만) 목격자가 눈을 뜨고, 법의학자가 범인과 공범 두 명을 가리킨다. 이후 목격자가 눈을 감는다.
6. 전원이 눈을 뜬다.

## 1.5 수사 3라운드
장면 타일은 6장으로 구성한다.
- "범행 장소" 타일 변형 중 1장(법의학자가 선택)
- "사인" 타일 1장
- 덱에서 뽑은 무작위 타일 4장

각 타일에는 6개의 항목이 있다. 총알 마커는 6개이고, 타일 한 장에는 마커를 1개만 올릴 수 있다.

각 라운드는 증거수집, 발표 순으로 진행한다.

- **R1 증거수집**
  - 법의학자가 마커를 한 개씩 타일의 항목 위에 올린다.
  - 올리는 속도에는 제한이 없다.
  - 첫 마커가 놓인 뒤부터 법의학자를 제외한 전원이 자유롭게 토론한다.
  - 한 번 놓은 마커는 옮길 수 없다.
  - 마커 순서와 망설임이 단서가 될 수 있다.
  - 여섯 번째 마커가 놓이면 증거수집이 끝난다.
- **R1 발표**
  - 짧은 토론 후, 법의학자의 왼쪽 플레이어부터 시계방향으로 한 명씩 약 30초씩 핵심 증거와 수단에 대한 의견을 발표한다.
  - 발표 중에는 끼어들 수 없다(해결 시도만 예외).
- **R2 증거수집**
  - 덱에서 타일 1장을 뽑아, 장소/사인을 제외한 기존 타일 4장 중 1장과 교체한다.
  - 교체되는 타일의 마커를 회수해서 새 타일의 항목 하나에 올린다.
  - 이후 토론하고 R2 발표를 한다.
- **R3**: R2와 같은 방식으로 교체하고 발표한다.
- 이벤트 타일(변형 규칙)은 R1이 끝난 뒤 덱에 섞는다. R2 또는 R3에서 뽑히면 내용을 읽고 효과를 적용한다.

## 1.6 사건 해결(Solve the Crime)
- 법의학자를 제외한 모든 플레이어(범인과 공범 포함)는 게임 중 언제든 딱 1회 시도할 수 있다.
- 시도 방법: 다른 플레이어 한 명을 정하고, 그 앞의 단서 1장과 수단 1장을 지목한다.
- 정답이면 즉시 게임이 끝나고 수사팀이 이긴다.
- 오답이면 법의학자는 "아니오"만 답한다(추가 정보 없음). 배지를 반납하고 이후 재시도는 불가하지만, 발표 참여는 계속한다.
- 마지막 플레이어의 3회차 발표가 끝나기 전까지 시도하지 않으면 기회를 잃는다.
- 정답 판정: 지목한 대상이 범인이고, 단서와 수단이 정답과 일치할 때 정답이다.

## 1.7 종료
- (a) 누군가 정답을 맞힌다. 반전이 없으면 수사팀이 승리한다.
- (b) 모든 플레이어가 기회를 잃는다. 범인팀이 승리한다.

## 1.8 반전(목격자가 있을 때만)
- 정답이 나온 뒤, 범인이 공범과 상의해서 한 명을 지목한다(재판 전에 조용히 제거할 사람).
- 지목된 사람이 목격자면 범인팀이 승리하고, 아니면 수사팀(목격자 포함)이 승리한다.

## 1.9 대화 황금률
- 법의학자는 총알 배치와 예/아니오 응답 외의 어떤 방법으로도(말, 표정, 시선 포함) 정보를 전달할 수 없다.
- 증거수집 단계에서는 자유롭게 말할 수 있고, 질문은 가능하며 답변은 선택이다.
- 발표 단계에서는 해결 시도 외에 끼어들 수 없다.

## 1.10 옵션(방 설정)
- 카드 수 3/4/5장
- 이벤트 타일 ON/OFF
- 발표 시간 20/30/45/60초/무제한(기본 30초)
- 공범, 목격자 ON/OFF
- (확장 훅만) 추가 역할을 꽂을 수 있게 Role 시스템을 플러그인 구조로 설계한다. 구현은 v2다.

## 1.11 디지털 변환으로 바뀌는 점
- 법의학자의 "예/아니오" 응답은 서버가 자동 판정해서 전송한다.
- 눈 감기 단계는 개인 화면 + 균일 타이밍으로 대체한다(4.4 참조).

## 1.12 룰북이 모호해서 내린 결정(README "가정"에 그대로 기록)
1. 해결 시도의 대상은 본인이 아닌 다른 플레이어다.
2. 발표 순서는 좌석 순서 기준이다. 좌석은 로비에서 무작위 배정하고 방장이 드래그로 수정할 수 있다. 법의학자의 다음 좌석부터 시계방향이다.
3. 이벤트 타일이 뽑히면, 효과를 적용하고 버린 뒤 같은 라운드에서 일반 타일을 한 장 더 뽑아 교체를 진행한다.
4. 반전 단계에서 범인이 지목할 수 있는 대상은 법의학자, 범인, 공범을 제외한 사람이다. 제한 시간은 60초이고, 시간 초과는 수사팀 승리로 처리한다.
5. "마지막 기회"는 3라운드 발표가 시작될 때 전원에게 경고하고, 마지막 발표자의 발표가 끝나는 순간 소멸한다(유예 없음).
6. 해결 시도 중에는 서버가 "시도 잠금"을 걸고(선착순), 타이머를 일시정지한다. 마법사(위자드)를 중도에 닫으면 시도는 소모되지 않는다. 최종 확정(꾹 누르기) 시점에만 소모된다.
7. 해결 시도 선택 UI 제한 시간은 20초다. 초과하면 취소 처리하며 소모되지 않는다.

# 2. 아키텍처
- TypeScript 모노레포(pnpm): `apps/web`, `apps/server`, `packages/shared`.
  - web: React + Vite + PWA, Zustand, Tailwind, Framer Motion, i18next.
  - server: Node + Colyseus(또는 Socket.IO), 페이즈 상태머신은 XState.
  - shared: 타입, zod 스키마, 순수 함수 규칙 엔진.
- 서버 권위(server-authoritative) 구조다. 클라이언트에는 역할별 "뷰 프로젝션"만 보낸다.
  - 정답과 역할은 해당자에게만 전송한다.
  - 전체 브로드캐스트에는 정답, 역할, 범인 정보를 절대 넣지 않는다.
- 규칙 엔진은 UI와 완전히 분리한 순수 함수로 만든다. 시드 기반 RNG를 쓰며, 헤드리스 시뮬레이터(봇 4~12명)로 전체 게임을 돌려볼 수 있어야 한다.
- 방은 4자리 코드 + QR + 링크로 입장한다. 재접속 토큰(localStorage)으로 새로고침/끊김 후에도 복귀한다.
- 음성은 v1에서는 외부 음성(디스코드 등)이나 같은 방 오프라인 플레이를 전제로 하고, UI에 "음성 연결 권장" 안내를 둔다. `VoiceAdapter` 인터페이스만 정의하고 LiveKit은 v2다.

# 3. 모바일 레이아웃 원칙
- 기준 해상도는 390×844이고 최소 360×640이다. 세로 고정이다.
- `100dvh`, safe-area inset을 적용하고 body 스크롤은 없다. 내부 영역만 스크롤한다.
- 태블릿/PC에서는 max-width 480px를 중앙 정렬한다. 선택 기능으로 "테이블 모드"(≥768px, TV/태블릿에 공용 보드를 띄우고 폰은 컨트롤러로 쓰는 방식)를 만든다.
- 엄지 영역(하단)에 핵심 액션(해결, 내 정보, 메모)을 둔다. 터치 타깃은 44px 이상이다.
- 핵심 문제는 "최대 11명 × 8장 = 88장 카드를 작은 화면에서 비교하는 것"이다. 해법은 3단 구조(고정 증거 리본 / 용의자 스트립 / 선택된 용의자의 카드 8장)와 보조로 매트릭스 뷰를 두는 것이다.

## 3.1 수사 메인 화면(증거수집/발표 공통)
```
┌────────────────────────────┐
│ R2/3 ●●○  증거수집   ⏱ --   │ 상단바 44px
├────────────────────────────┤
│[장소][사인][T3][T4][T5][T6] │ 증거 리본 72px(가로 스크롤)
│            ▾ 보드 펼치기    │ 칩 탭 = 타일 상세
├────────────────────────────┤
│ (A)(B)(C)(D)(E)(F)(G) ▸    │ 용의자 스트립 64px
├──────────────┬─────────────┤
│ 🔎 단서(적색)  │ 🧰 수단(청색) │ 헤더 28px
│ [ 카드 ]      │ [ 카드 ]     │
│ [ 카드 ]      │ [ 카드 ]     │ 카드 2열×4행(각 ≥64px 높이)
│ [ 카드 ]      │ [ 카드 ]     │
│ [ 카드 ]      │ [ 카드 ]     │
├──────────────┴─────────────┤
│ [📓 메모] [🪪 내 정보] [🔍 해결]│ 하단 독 56px+safe-area
└────────────────────────────┘
```
- 증거 리본은 항상 상단에 고정한다. 용의자 카드를 훑는 동안에도 법의학자가 고른 6개 항목이 계속 보여야 한다. 이것이 가시성의 핵심이다.
- 리본의 각 칩에는 타일 제목과 선택된 항목을 2줄로 표시한다. 새로 놓인 마커는 칩이 "팝"하며 강조된다.
- 리본을 탭하거나 펼치면 "스트링 보드"(코르크보드에 사진이 핀으로 꽂힌 메타포)로 6개 타일 전체를 보여 준다. 선택되지 않은 5개 항목은 흐리게 표시한다. 선택되지 않은 항목도 추리 맥락이기 때문이다.
- 용의자 스트립에는 각 플레이어의 아바타, 이름, 배지 상태(🪪 보유 / 💥 소진), 발표 중 링 표시를 둔다. 스트립을 탭하거나 카드 영역을 좌우 스와이프하면 용의자가 바뀐다.
- 카드 한 장의 구성: 좌측 아이콘 + 라벨(≤10자). 단서는 적색 + 돋보기류 아이콘, 수단은 청색 + 도구류 아이콘으로 색과 모양을 함께 쓴다(색각 이상 대응). 카드를 길게 누르면 확대되고, 탭하면 개인 메모 마킹을 순환한다(없음 → ◯ 유력 → △ 보류 → ✕ 제외). 메모는 본인에게만 보인다.
- "전체 보기(매트릭스)" 바텀시트: 행은 플레이어, 열은 8장이며 아이콘 칩 형태다. 한눈에 비교하고 내 메모 마킹 색을 함께 보여 준다.

## 3.2 법의학자 보드(증거수집)
```
┌────────────────────────────┐
│ 총알 트레이  ◉◉◉○○○ (남은 3) │
├────────────────────────────┤
│ ┌ 타일1: 사인 ───────────┐  │
│ │[항목1][항목2][항목3]    │  │
│ │[항목4][항목5][항목6]    │  │ 항목 탭=선택, 길게 누르면(0.6초) 확정
│ └────────────────────────┘  │
│ ┌ 타일2 … (세로 스크롤, 총 6장)│
├────────────────────────────┤
│ ▲ 내 정답 패널(접이식·나만 봄)│ 정답 카드 2장, 범인/공범 이름
└────────────────────────────┘
```
- 확정 전에는 "미리보기 마커"가 따라다니고, 확정되면 "탁" 소리/진동과 함께 항목 위에 박힌다. 확정 후에는 되돌릴 수 없다.
- (옵션, 기본 ON) 법의학자의 손가락이 한 항목 위에 0.8초 이상 머물면 다른 사람 화면에서 그 항목이 은은하게 빛난다. 룰북의 "망설임도 단서"를 디지털로 구현한 것이다.

## 3.3 발표 화면(스포트라이트)
```
┌────────────────────────────┐
│ R2 발표 3/9        ⏱ 0:21  │
│        ( 큰 아바타 )        │ 발표자 스포트라이트, 나머지는 어둡게
│    "민수의 발표 중…"         │
│ [이론 핀: 용의자·단서·수단]   │ 발표자만 편집, 전원에게 표시(구속력 없음)
├────────────────────────────┤
│ 증거 리본(고정) + 카드 열람 가능│
│ [🔍 해결 시도] ← 언제든 가능   │
└────────────────────────────┘
```
- 발표 중에는 채팅/리액션이 잠기고, 해결 시도만 가능하다(끼어들기 금지 규칙 반영).
- "이론 핀"은 발표자가 용의자 1명 + 단서 1장 + 수단 1장을 임시로 핀 꽂아 의견을 시각화하는 기능이다. 해결 시도와 시각적으로 명확히 구분한다(핀 = 중립 톤, 해결 = 적색 경보 톤). 방 설정에서 끌 수 있다.
- 시도 순서에서 이미 발표를 마친 사람과 앞으로 할 사람이 한눈에 보이도록 스트립 위에 순서 점을 표시한다.

## 3.4 해결 시도 마법사(전체 화면 시트)
1. 용의자 선택(스트립, 본인 제외)
2. 단서 선택(그 사람의 단서 4장)
3. 수단 선택(그 사람의 수단 4장)
4. "꾹 눌러 지목"(1.2초 홀드, 진행 링)

- 상단 진행 바 4단계와 20초 제한 타이머를 표시한다. 닫으면 소모되지 않는다. 홀드 확정 시에만 배지가 소모된다.
- 시작하는 순간 전원 화면에 "누군가 사건을 해결하려 합니다!" 오버레이가 뜨고, 타이머가 정지하고, 다른 사람의 시도는 잠긴다.
- 결과: 오답이면 화면이 흔들리고, "아니오" 도장이 찍히고, 배지가 깨진다(추가 정보 없음). 정답이면 "CASE CLOSED" 스탬프와 함께 종료 연출로 넘어간다.

# 4. 씬(화면) 흐름
각 씬은 `PhaseShell`로 감싸고 전환은 0.4초 이내로 한다.

1. **홈**: 닉네임/아바타 선택, 방 만들기, 코드 입장.
2. **로비**: 코드 + QR, 플레이어 목록과 준비 상태, 좌석 원형 뷰, 방장 설정 시트(1.10 옵션), 인원별 자동 역할 구성 요약.
3. **카드 분배(DEAL)**: 법의학자가 지정된다(룰북 권장: 표현력 좋은 사람. 방 설정에서 랜덤/방장 지정/자원 선택). 카드가 각 플레이어 앞으로 날아가 공개 배치된다(약 3초). 법의학자의 카드는 버려지는 연출이 나온다.
4. **역할 공개(ROLE_REVEAL)**: 개인 화면에서 "꾹 눌러 확인(hold-to-reveal)", 손을 떼면 즉시 가려진다. 역할 도시에(dossier) 카드가 뒤집히며 역할, 승리 조건, 아는 정보(1.2 표)를 보여 준다. 전원 확인 완료 시 다음으로 넘어간다.
5. **밤/범행(CRIME_NIGHT)**: 4.4 참조.
6. **현장 도착(SCENE_INTRO)**: 네온 비 내리는 시네마틱(2~3초) 후 범행 장소 타일이 공개된다. 이 순간부터 "공개 증거 열람" 화면이 열린다.
7. **증거수집(EVIDENCE_COLLECTION)**: 3.1/3.2. 자유 토론(텍스트 채팅 + 빠른 리액션), 법의학자는 채팅이 비활성화된다.
8. **발표(PRESENTATION)**: 3.3. 한 명씩 스포트라이트, 타이머 링, 다음 발표자 미리 표시.
9. **라운드 전환(ROUND_TRANSITION)**: 법의학자가 교체할 타일을 선택하고 새 타일이 뒤집히며 교체되는 애니메이션이 나온다. 마커는 회수되어 새 타일 위로 이동한다. 이벤트 타일이 뽑히면 이벤트 모달(전원 확인)을 띄운다.
10. **해결 시도(SOLVING)**: 3.4.
11. **판결(VERDICT)**: 정답이면 CASE CLOSED 스탬프. 반전 조건이면 다음 씬으로, 아니면 결과로 간다.
12. **반전(REVERSAL)**: 범인/공범에게만 지목 UI와 비밀 채팅이 열린다. 나머지는 "범인이 재판 전 마지막 수를 두는 중…" 화면과 60초 카운트다운을 본다.
13. **결과(RESULT)**: 정답 공개(범인 카드 중 정답 2장 하이라이트), 전원의 역할 공개, 승리 팀 연출, "사건 재구성" 타임라인(각 라운드의 마커 위치, 발표 요약, 해결 시도 기록), 재대결(법의학자 교대) 버튼.

## 4.4 밤 단계: 정보 누출 방지 설계
- 모든 클라이언트가 동일한 타임라인을 따른다: 안내(3초) → 범인 단계(고정 25초) → 목격자 단계(고정 10초, 목격자가 없어도 동일하게 진행) → 종료 안내.
- 범인이 일찍 확정해도 단계를 조기 종료하지 않는다. 항상 고정 시간을 소비한다.
- 비당사자 화면은 모두 동일한 어두운 화면이다(소리, 진동 없음). 당사자 화면에도 소리/진동을 쓰지 않는다.
- 목격자에게는 범인/공범 두 사람의 이름을 역할 표시 없이 무작위 순서로 보여 준다.
- 법의학자 화면에는 범인이 정답 두 장을 고르는 순간이 실시간으로 전달된다(범인, 공범 정체 포함).
- 같은 방에서 플레이하는 경우를 위해, 당사자 UI는 최저 밝기 테마 + 2탭 선택으로 곁눈질 노출을 줄인다.

# 6. 몰입감·비주얼·사운드·햅틱
- **무드**: 홍콩 네온 느와르. 짙은 남색/검정 배경 + 네온 마젠타(단서)와 네온 시안(수단)을 의미색으로 고정한다. 폰트는 Pretendard 또는 Noto Sans KR(본문)과 개성 있는 디스플레이 폰트(제목)를 쓴다. `word-break: keep-all`.
- **배경**: CSS/SVG로 비, 네온 보케, 은은한 네온 깜빡임. WebGL은 쓰지 않는다.
- **메타포**: 카드는 증거 태그/폴라로이드, 타일은 현장 사진 보드, 마커는 놋쇠 총알, 배지는 형사 배지로 한다.
- **페이즈별 조명**: 로비 = 따뜻한 네온 / 밤 = 거의 검정 / 수사 = 차가운 시안 / 발표 = 스포트라이트 비네팅 / 해결 = 적색 경보 맥동 / 결과 = 승리 팀 색.
- **SFX**(모두 짧게): 마커 "탁", 타일 교체 "촤락", 도장 "쿵", 오답 "삑", 정답 스팅어, 카메라 셔터, 타이머 마지막 5초 틱. 밤 단계는 무음이다.
- **햅틱**: 마커 확정(짧은 진동 1회), 해결 시작(길게 1회), 오답(짧게 2회), 정답(패턴). 밤 단계는 진동 없음, 설정에서 끌 수 있다.
- **모션 규칙**: 전환 ≤0.4초, 강조 ≤0.2초. 동시에 움직이는 요소는 3개 이하로 제한한다. `prefers-reduced-motion`이면 페이드로 대체한다.
- 모든 연출은 "정보를 가리지 않는 것"이 우선이다. 증거 리본과 카드 가독성을 해치면 연출을 줄인다.

# 7. 접근성·성능
- 색에만 의존하지 않는다(색 + 아이콘 + 테두리 패턴). 본문 15px 이상, 캡션 13px 이상, 터치 타깃 44px 이상.
- 스크린 리더 라벨(카드 종류, 소유자, 마커 위치 포함).
- 초기 JS는 gzip 기준 250KB 이하를 목표로 한다. 중급 안드로이드에서 60fps를 목표로 한다. 이미지는 SVG 위주로 하고, 초기 로드 3MB 이하.
- 오프라인 shell(PWA)과 홈 화면 설치를 지원한다.

# 8. 데이터 모델과 프로토콜
```ts
type Role = 'forensic'|'murderer'|'accomplice'|'witness'|'investigator';
type Phase = 'LOBBY'|'DEAL'|'ROLE_REVEAL'|'CRIME_NIGHT'|'SCENE_INTRO'
  |'EVIDENCE_COLLECTION'|'PRESENTATION'|'ROUND_TRANSITION'|'SOLVING'
  |'VERDICT'|'REVERSAL'|'RESULT';

interface Card { id: string; kind: 'clue'|'means'; label: string; icon: string }
interface SceneTile {
  id: string; kind: 'location'|'cause'|'hint'|'event';
  title: string; options: string[] /* 길이 6 */; eventText?: string;
}
interface Player { id: string; name: string; seat: number; connected: boolean;
  hasBadge: boolean; cards: Card[] /* 공개 */ }
interface Solution { clueId: string; meansId: string; murdererId: string }

// 공개 상태(전원에게): phase, round, players(공개 정보), tiles, markers(타일→항목), presenterId, timer, badge 상태, solveLock
// 비공개 상태(해당자에게만): myRole, 역할별 정보(정답/범인/공범/목격자의 후보 2인), 내 메모
```
- **클라 → 서버**: `join`, `ready`, `setSettings`, `confirmRole`, `crimeSelect`, `placeMarker`, `replaceTile`, `endPresentation`, `startSolve`, `commitSolve`, `cancelSolve`, `reversalPick`, `rematch`.
- **서버 → 클라**: 역할별 projection `state`, `event`(연출 트리거), `error`.
- 모든 액션은 `phase × role × 순서`로 서버에서 검증한다. 멱등하게 처리하고, 재접속 시 마지막 projection을 즉시 재전송한다.

# 9. 엣지 케이스
- 법의학자 연결 끊김: 60초 대기 후 방장이 "중단/재시작"을 선택한다. 그 사이 모든 타이머를 정지한다.
- 발표자 연결 끊김: 15초 후 자동으로 발표를 건너뛴다.
- 범인/공범 연결 끊김: 게임은 계속 진행한다. 서버가 정답을 보관한다. 이탈한 플레이어의 카드는 지목 대상으로 남는다.
- 플레이어 이탈 시 배지는 소진 처리하고 자동으로 발표를 건너뛴다.
- 동시 해결 시도: 서버가 선착순으로 잠금을 건다.
- 중복 탭/네트워크 지연: 클라이언트는 낙관적 UI를 쓰되 서버 응답으로 보정한다.
- 인원 변경(4~12) 시 역할 구성을 자동으로 재계산한다. 규칙 위반 조합(예: 공범 없이 목격자)은 방 설정에서 막는다.

# 10. 오리지널 콘텐츠 시드(JSON으로 별도 파일, 한국어)
- 단서 카드 ≥ 60장, 수단 카드 ≥ 60장(12인 × 5장 난이도까지 감당). 라벨은 ≤10자이고, 서로 의미가 겹치지 않게 만든다.
  - 예시(참고용 방향): 단서 "젖은 우산", "끊어진 목걸이", "형광 립스틱 자국", "깨진 안경테" / 수단 "다용도 칼", "독이 든 차", "전선", "유리병".
- 범행 장소 타일 변형 3종, 사인 타일 1종, 힌트 타일 ≥ 14종, 이벤트 타일 6종. 타일마다 6개 항목이고, 항목은 ≤8자이다.
  - 힌트 타일은 서로 직교하는 관점이어야 한다(예: 시간대, 범인의 인상, 현장 분위기, 피해자와의 관계, 범행 동기, 단서의 상태 등).
  - 이벤트는 구현 가능한 단순 효과로 한다(예: "정전: 이번 라운드 발표 시간 -10초", "소문: 한 명을 지목해 짧은 질문을 하나 받는다" 등 오리지널로).
- 수위는 가벼운 느와르 톤을 유지한다. 잔혹/선정적 표현은 금지한다.

# 11. 테스트와 수용 기준
**규칙 엔진 단위 테스트(최소)**: 역할 배정(4,5,6,8,12인), 카드 분배(3/4/5장), 법의학자 카드 제외, 장면 타일 구성(6장 + 마커 6개), 타일당 마커 1개 제한, 마커 이동 불가, R2/R3 교체 시 마커 회수 후 재배치, 발표 순서(법의학자 다음 좌석부터 시계방향), 오답 시 배지 소진과 재시도 불가, 정답 판정(대상 + 단서 + 수단), 모든 기회 소진 시 범인팀 승, 마지막 발표 후 기회 소멸, 반전(목격자 지목 성공/실패/시간 초과), 이벤트 타일 처리(3번 결정), 동시 해결 시도 잠금.

**보안/누출 테스트**: 각 클라이언트가 받는 WebSocket 페이로드를 캡처해, 비인가 클라이언트에는 정답/역할/범인 정보가 없음을 자동 검증한다. 밤 단계에서 역할별 응답 타이밍 편차가 50ms 미만임을 검증한다.

**E2E(Playwright)**: 봇 6명과 12명으로 전체 게임 완주(정답 승리, 범인팀 승리, 반전 승리 시나리오).

**모바일 수용 기준**:
- 360×640과 390×844에서 가로 스크롤이 없다.
- 모든 터치 타깃이 44px 이상이다.
- 수사 메인 화면에서 증거 리본, 용의자 스트립, 카드 8장, 하단 독이 스크롤 없이 한 화면에 들어온다.
- 스크린샷 테스트를 첨부한다.

# 12. 단계별 산출물과 보고 형식
- **M1**: `packages/shared` 규칙 엔진 + 헤드리스 시뮬레이터 + 단위 테스트.
- **M2**: 서버(상태머신, projection, 재접속) + 웹 클라이언트(홈 → 로비 → 역할 → 밤 → 수사 → 해결 → 결과) + 임시 스타일.
- **M3**: 비주얼/사운드/햅틱 폴리싱, 이벤트 타일, 테이블 모드(선택), 접근성/성능 점검.
- **M4(선택)**: 확장 역할 플러그인
- 각 마일스톤마다 보고한다: 실행 방법, 변경 파일, "규칙 번호 ↔ 테스트 이름" 추적표, 스크린샷, 남은 가정과 리스크.
- 최종 산출물: 실행 가능한 저장소, README(설치/실행/환경변수/배포, 가정 목록, IP 주의), 시드 콘텐츠 JSON, 테스트 리포트.
