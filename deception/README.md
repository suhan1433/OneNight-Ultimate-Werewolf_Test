# 네온 사건파일

4~12인 실시간 채팅 추리 게임. `instruction.md`의 M1부터 구현한 독립 pnpm 모노레포다. 한국어, 모바일 우선이며 기존 아발론 및 다른 게임의 소스·실행 포트를 변경하지 않는다.

## 설치와 실행

Node.js 22 이상. 아래 명령은 모두 `deception` 디렉터리에서 실행한다. pnpm이 설치돼 있으면 `npx pnpm@10.11.0` 대신 `pnpm`을 사용해도 된다.

```bash
npx pnpm@10.11.0 install --frozen-lockfile
npx pnpm@10.11.0 dev
```

웹: http://localhost:5176 · 서버: http://localhost:3004 · 상태 확인: http://localhost:3004/health.

서로 다른 브라우저/시크릿 창 또는 기기에서 4명 이상 접속한다. 한 명이 닉네임을 정하고 방을 만든 뒤 4자리 코드·링크·QR로 초대한다. 전원이 준비하면 방장이 시작한다. 같은 컴퓨터에서 여러 명을 테스트할 때는 **독립 브라우저 컨텍스트**를 사용한다. 같은 프로필의 여러 탭은 같은 플레이어 세션을 공유하며, 새 탭이 이전 탭을 대체한다.

같은 LAN의 휴대전화에서는 `http://<개발 PC의 LAN IP>:5176`으로 접속한다. 웹 개발 서버가 Socket.IO를 프록시하므로 휴대전화에 `localhost:3004`를 지정하지 않는다. 개발 서버는 같은 호스트의 Origin만 허용한다. PWA 설치·오프라인 캐시는 HTTPS 또는 localhost에서 동작하며, 실제 멀티플레이에는 온라인 연결이 필요하다.

## 검증과 시뮬레이터

```bash
npx pnpm@10.11.0 test
npx pnpm@10.11.0 typecheck
npx pnpm@10.11.0 build
npx pnpm@10.11.0 simulate 6 demo-seed
npx pnpm@10.11.0 simulate 12 demo-seed

# 실제 독립 Chromium 컨텍스트: 로비, 6인 정답, 12인 반전
npx pnpm@10.11.0 --filter @deception/web exec playwright install chromium
npx pnpm@10.11.0 test:e2e
```

시뮬레이터의 인자: 인원(4~12), 시드 문자열. 정답, 배지 소진, 최종 발표 종료를 실행하며, 8인 이상은 목격자 지목 성공·실패·시간 초과도 실행한다. 이 드라이버는 검증용 전지적 봇이며 사람 수준의 추리 AI가 아니다. 실제 방에는 봇을 추가하지 않는다.

테스트는 Node의 기본 테스트 러너와 Playwright를 사용한다. [M1 보고서](docs/M1.md)에 규칙 번호와 테스트 이름을 연결했다. [M2 보고서](docs/M2.md)와 [최종 검증 결과](docs/TEST_REPORT.md)에서 실제 멀티플레이 검증을 확인할 수 있다. 스크린샷은 `docs/screenshots`, Playwright JSON은 `docs/e2e-results.json`에 생성된다.

## 구조

```text
apps/web              React + Vite + Zustand + Tailwind + Framer Motion + i18next
apps/server           Node HTTP + Socket.IO + XState actor, 방과 인증 세션 관리
packages/shared       zod 프로토콜, 순수 규칙 엔진, 정보 projection, 시드 RNG
  src/content/ko.json 한국어 오리지널 카드·장면·이벤트
docs                  마일스톤 보고, 규칙 추적표, 스크린샷
```

서버의 XState transition actor가 공유 엔진을 실행하고, 허용 목록으로 구성한 `project()` 결과만 각 플레이어의 소켓으로 보낸다. 클라이언트 요청의 `actorId`는 허용하지 않으며 인증된 소켓의 세션에서 결정한다. 서버 시각만 타이머를 진행한다. 범행 선택·개인 역할 확인은 비당사자에게 이벤트를 보내지 않고, 밤의 공통 상태는 고정 주기의 heartbeat로 전달한다. RNG 시드는 재현용으로만 사용하며 외부에 공개하지 않는다. 방 코드와 재접속 토큰에는 암호학적 난수를 사용한다.

공개 채팅은 첫 마커 이후, 발표 채팅은 해당 발표자에게만 허용된다. 법의학자는 결과 이전에 공개 채팅을 할 수 없다. 반전에서만 범인·공범 전용 채널이 열린다. 이 채널의 메시지는 수사팀에게 보내지 않는다. 채팅 길이·빈도를 서버에서 제한하고 React의 기본 텍스트 이스케이프를 사용한다.

개인 메모는 브라우저 localStorage에만 보관한다. 재접속 토큰도 localStorage에 보관하며 게임 서버가 토큰을 검증한다. `VoiceAdapter`는 인터페이스만 제공한다. **이번 구현은 사용자 요청대로 채팅 진행**을 기본으로 하며 외부 음성 연결을 요구하지 않는다.

## 배포와 환경변수

### 기존 게임 사이트와 함께 Render에 배포

저장소 루트 또는 `apps/server/Dockerfile`로 빌드하면 `/deception/`에서 실행된다.
두 Docker 구성은 deception의 pnpm 의존성을 lockfile로 설치하고 통합 빌드를 실행한다.
웹 출력은 루트 `apps/web/dist/deception`에 생성되며, 서버는 내부 포트 `3007`에서 실행된다.
Nginx가 `/api/deception/socket/`을 해당 서버로 전달한다. Render 환경의 `PORT`는
공용 Nginx 포트이므로 `3007`로 바꾸지 않는다. 별도의 `VITE_SERVER_URL`은 필요 없다.

통합 빌드만 실행하려면 저장소 루트에서 `npm run build:deception`, 게임 선택 화면을
포함한 전체 Render 빌드는 `npm run build:render`를 사용한다. 일반 `pnpm dev`와
`pnpm build`는 계속 독립 실행용 `/` 경로를 사용한다. 아이콘·manifest·서비스 워커는
통합 빌드에서 `/deception/` 아래로 제한되므로 다른 게임의 PWA 캐시에 관여하지 않는다.

컨테이너의 실제 Nginx를 경유하는 배포 검증:

```bash
# 저장소 루트에서
docker build -f apps/server/Dockerfile -t afterhours-deception .
docker run --rm -d --name afterhours-deception-test -p 127.0.0.1:18880:10000 afterhours-deception
npx pnpm@10.11.0 --dir deception --filter @deception/web test:render
docker stop afterhours-deception-test
```

선택 화면 → `/deception/` 이동, 두 브라우저의 방 생성·초대·채팅·새로고침 복귀,
하위 경로의 아이콘·manifest·서비스 워커, 다른 게임의 캐시 보존을 검사한다.
다른 테스트 주소는 `RENDER_TEST_URL`로 지정할 수 있다.

### 독립 배포

```bash
npx pnpm@10.11.0 build
PORT=3004 npx pnpm@10.11.0 start
```

빌드 후 Node 서버 하나가 웹 정적 파일과 Socket.IO를 함께 제공한다. 정적 호스팅만으로는 게임 서버를 실행할 수 없다. 장기 실행 Node 프로세스에서 운영하고, 역방향 프록시에서 `/socket.io` WebSocket upgrade와 polling을 모두 전달한다.

| 변수              | 위치     | 기본값 / 용도                                                                   |
| ----------------- | -------- | ------------------------------------------------------------------------------- |
| `PORT`            | server   | `3004`                                                                          |
| `WEB_ORIGIN`      | server   | 별도 웹 도메인이 있을 때 허용 Origin을 쉼표로 지정. 미설정이면 같은 Host만 허용 |
| `VITE_SERVER_URL` | web 빌드 | 기본은 웹과 같은 Origin. 서버를 별도로 배포할 때 지정                           |
| `VITE_SOCKET_PATH` | web 빌드 | 기본은 `/socket.io`, 통합 빌드는 `/api/deception/socket/`. 별도 프록시 경로가 있을 때 지정 |

현재 방·타이머·토큰은 단일 서버 메모리에 저장된다. 서버를 재시작하면 방과 토큰이 사라진다. 다중 인스턴스와 프로세스 재시작 복구에는 공유 저장소와 방 단위 직렬화가 추가로 필요하다. 연결이 모두 끊긴 방은 30분 후 정리한다.

## 가정

명세 1.12의 결정을 다음과 같이 적용했다.

1. 해결 시도의 대상은 본인이 아닌 다른 플레이어다.
2. 발표 순서는 좌석 순서 기준이다. 좌석은 로비에서 무작위 배정하고 방장이 드래그로 수정할 수 있다. 법의학자의 다음 좌석부터 시계방향이다.
3. 이벤트 타일이 뽑히면, 효과를 적용하고 버린 뒤 같은 라운드에서 일반 타일을 한 장 더 뽑아 교체를 진행한다.
4. 반전 단계에서 범인이 지목할 수 있는 대상은 법의학자, 범인, 공범을 제외한 사람이다. 제한 시간은 60초이고, 시간 초과는 수사팀 승리로 처리한다.
5. "마지막 기회"는 3라운드 발표가 시작될 때 전원에게 경고하고, 마지막 발표자의 발표가 끝나는 순간 소멸한다(유예 없음).
6. 해결 시도 중에는 서버가 "시도 잠금"을 걸고(선착순), 타이머를 일시정지한다. 마법사(위자드)를 중도에 닫으면 시도는 소모되지 않는다. 최종 확정(꾹 누르기) 시점에만 소모된다.
7. 해결 시도 선택 UI 제한 시간은 20초다. 초과하면 취소 처리하며 소모되지 않는다.

추가 디지털 변환 결정:

- 초기 로비 좌석은 입장 시 무작위 위치에 배정하고, 방장이 드래그 또는 모바일용 앞으로 이동 버튼으로 수정한다. 게임 시작 시 이 좌석 순서를 보존한다.
- 밤은 안내 3초 → 범행 25초 → 목격자 10초 → 종료 2초, 총 40초다. 목격자가 없어도 동일하다. 범인이 시간 안에 고르지 않으면 서버가 자기 카드에서 시드 기반으로 한 장씩 선택한다.
- 법의학자가 현장 도착 3초 동안 장소를 고르지 않으면 기본 장소를 사용한다. 이미 확정된 범행 정답은 바꿀 수 없다.
- 마지막 마커 뒤 토론 유예는 10초다. 법의학자가 먼저 발표를 시작할 수 있다. 교체 타일에도 같은 유예를 적용한다.
- 법의학자도 대기실·결과 화면에서는 채팅할 수 있다. 밤·해결 시도·반전 대기 화면의 공개 채팅은 잠근다.
- 자유 토론과 공개 카드 비교를 모바일 탭으로 전환한다. 카드 보기에서 채팅으로 돌아가거나 전체 비교·도움말·나가기를 열려면 상단 단계 이름의 `▾` 수사 메뉴를 누른다.
- 이벤트는 오리지널 6종이며 현재 라운드 발표 시간을 줄이거나 늘리거나 무제한으로 바꾼다. 이벤트는 자동 적용하고 기록한다. 전원 확인을 기다리는 모달은 후속 작업이다.
- 법의학자 연결 끊김은 모든 타이머를 정지한다. 복귀하면 멈춘 시간을 보정한다. 60초 이후 방장이 중단하면 같은 방의 대기실로 돌아가 다시 시작할 수 있다.
- 명시적으로 나간 플레이어의 카드는 사건이 끝날 때까지 남고 배지는 소진된다. 연결 끊김만으로는 즉시 배지를 잃지 않으며 재접속할 수 있다. 연결이 끊긴 발표자는 15초 후 넘어간다.
- M1 엔진 자체가 페이즈 전이를 관리하고 M2 XState actor가 명령·시간 이벤트·오류를 직렬 처리한다. 별도의 두 번째 규칙 구현을 만들지 않는다.

## 현재 범위와 후속 작업

M1 규칙 엔진과 M2 실시간 서버·게임 화면을 제공한다. 네온 UI, Web Audio 효과음/진동 설정, 개인 메모, 비교 보드, PWA shell도 포함한다. M3의 이벤트 전원 확인 모달, 이론 핀, 마커 망설임 전달, 상세 발표 요약과 전체 접근성 감사는 후속 작업이다. 테이블 모드와 확장 역할·실제 음성 어댑터는 선택/v2 범위다. i18next에 한국어 네임스페이스를 제공하며 추가 화면 문구의 완전한 번역 분리는 후속 작업이다.
