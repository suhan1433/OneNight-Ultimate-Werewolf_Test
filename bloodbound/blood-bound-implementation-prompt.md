# Blood Bound 게임 구현용 최종 프롬프트

아래 명세에 따라 Blood Bound 디지털 보드게임을 구현하라. 이 문서는 규칙과 구현 정책의 최종 기준이다. 명세 사이에 충돌이 있으면 1) 디지털 구현 정책, 2) 캐릭터별 규칙, 3) 공통 게임 규칙, 4) 기술·UI 요구사항 순서로 적용한다. 어떤 경우에도 규칙을 임의로 추가하거나 공식 룰북 규칙으로 오인해 덮어쓰지 않는다. 다만 이 문서에서 이미 확정한 정책으로 해소할 수 있는 모호성은 질문하지 말고 그대로 구현한다. 실제 모순이나 실행 불가능한 요구가 남으면 해당 코드 경로를 임의로 완성하지 말고 결과 보고에 명시한다.

## 1. 프로젝트 목표와 범위

- 게임명: Blood Bound
- 플레이 인원: 6~12명
- 장르: 정체 은닉, 추리, 블러핑, 클랜 대결
- 클랜: Rose, Beast
- 홀수 인원(7, 9, 11명): Secret Order 소속 Inquisitor 1명 포함
- MVP: 한 기기에서 여러 사람이 번갈아 플레이하는 Pass-and-Play
- 온라인 멀티플레이는 구현하지 않지만 서버 권한 엔진, 플레이어별 비공개 상태, 재접속, 로그 재생으로 확장할 수 있는 구조를 유지한다.
- 모든 대화는 공개적으로 진행한다. 게임 내 비밀 대화 기능은 제공하지 않는다. 플레이어는 자기 정체에 대해 거짓말할 수 있지만 규칙 데이터, 토큰, 이벤트를 조작할 수 없다.

완성된 실행 가능한 앱을 구현한다. 규칙을 React 컴포넌트 안에 넣지 않는다. 구현 순서는 데이터와 규칙을 먼저 완성하고, 엔진 테스트를 통과시킨 뒤 상태 관리, 정보 보호, UI, 애니메이션, 통합 검증 순으로 진행한다. 각 단계가 끝날 때 실제 파일과 검증 결과를 확인하고 작업을 이어간다.

## 2. 기술 스택 및 구조 원칙

- React, TypeScript, Vite, CSS Variables, SVG
- Vitest, React Testing Library
- 규칙 엔진은 UI와 독립된 순수 TypeScript 모듈로 작성한다.
- 핵심 인터페이스는 reduce(state, action) → { state, events } 또는 { error }다.
- 입력 상태를 직접 변경하지 않는다. 결정론적 상태 전이와 시드 기반 난수를 사용한다.
- 능력은 캐릭터별 핸들러 맵에 등록한다. Trigger, Conditions, Target Rules, Effects, Resolution Order, Events를 분리한다.
- 내부 GameState와 플레이어별 ViewModel을 분리한다. UI는 승패나 규칙을 판단하지 않고 엔진의 결과만 표시한다.
- 공개 이벤트와 비공개 이벤트를 구분한다. 각 플레이어에게 제공할 데이터는 별도 투영 함수로 만든다.
- 최소 데이터 모델: GameState, Player, Character, Clan, Rank, Affiliation, Clue, Wound, Token, Ability, Equipment, DaggerHolder, ActivePlayer, AttackContext, Intervention, LeaderState, Curse, GameEvent, VictoryResult, RandomSeed.

## 3. 게임 목표와 승리

각 클랜은 상대 클랜의 현재 리더를 찾아 포획하려 한다. 플레이어가 네 번째 상처를 받으면 즉시 포획되고 게임이 종료된다.

일반 승리 판정은 포획을 일으킨 행위자를 기준으로 한다.

- 행위자가 Rose 또는 Beast 소속이면, 포획 대상이 그 행위자의 상대 클랜 리더일 때 행위자 클랜 승리다.
- 그 외에는 행위자의 상대 클랜 승리다. 따라서 자기 클랜 리더 포획과 비리더 포획은 모두 행위자의 패배다.
- 포획을 일으킨 행위자가 Inquisitor라면 일반 승리 클랜은 포획 대상이 Rose이면 Beast, Beast이면 Rose로 판정한다. Inquisitor는 Rose/Beast 어느 쪽에도 속하지 않는다.
- 능력으로 네 번째 상처가 발생한 경우 포획 유발자는 그 능력을 사용한 플레이어다. Berserker 반격의 포획자는 Berserker다.
- 포획 대상이 Inquisitor면 다른 판정보다 먼저 Inquisitor 단독 승리를 확정한다.
- Inquisitor 직접 포획이 아니면 일반 클랜 승리를 계산한 다음 모든 Curse를 공개한다. 일반 승리 클랜의 현재 리더가 True Curse를 가지고 있으면 Inquisitor가 승리를 가로채 단독 승리한다. True Curse가 리더가 아닌 플레이어에게 있으면 효과가 없다.

VictoryResult는 최소한 capturedPlayer, captor, captorClan, capturedClan, currentLeaders, winningClan, inquisitorOverride, victoryReason을 저장한다. 최종 승리자는 Rose, Beast 또는 Inquisitor 중 하나다. 포획 발생 후 나머지 상처, 능력, 단검 이동, 턴 시작은 실행하지 않는다.

## 4. 캐릭터 데이터

각 클랜은 랭크 1~9 캐릭터를 각각 한 명씩 가진다. 게임에 포함된 캐릭터 중 해당 클랜 랭크 번호가 가장 작은 플레이어가 초기 리더다. Elder가 Quill을 사용하면 Elder를 리더 후보에서 제외하고 같은 클랜 나머지 참가자 중 랭크 번호가 가장 큰 플레이어를 새 리더로 즉시 지정한다. 참가자가 한 명뿐이라 새 리더 후보가 없으면 리더 변경 능력은 사용할 수 없는 상태로 처리하고 오류 이벤트를 남긴다.

각 일반 캐릭터는 clan, rank, name, affiliations(정확히 2 슬롯), clue, ability를 가진다. Clue는 실제 클랜과 독립된 필드다. Own Clan은 본인 클랜 아이콘, Opposite Clan은 상대 클랜 아이콘이다.

| Rank | 이름 | Rose Affiliation | Beast Affiliation | Clue |
|---:|---|---|---|---|
| 1 | Elder | Rose, Rose | Beast, Beast | Own Clan |
| 2 | Assassin | Unknown, Unknown | Unknown, Unknown | Own Clan |
| 3 | Harlequin | Unknown, Unknown | Unknown, Unknown | Opposite Clan |
| 4 | Alchemist | Unknown, Unknown | Unknown, Unknown | Own Clan |
| 5 | Mentalist | Rose, Rose | Beast, Beast | Own Clan |
| 6 | Guardian | Rose, Rose | Beast, Beast | Own Clan |
| 7 | Berserker | Rose, Unknown | Beast, Unknown | Own Clan |
| 8 | Mage | Rose, Unknown | Beast, Unknown | Own Clan |
| 9 | Courtesan | Rose, Unknown | Beast, Unknown | Own Clan |

Affiliation 토큰 적법성은 아이콘 종류만이 아니라 카드에 해당 아이콘이 나온 횟수에서 이미 보유한 같은 종류 토큰 수를 뺀 값으로 판단한다. 같은 종류 아이콘이 2개면 같은 토큰을 최대 2개까지 보유할 수 있다. 이 프로젝트에서는 중복 Affiliation 토큰 허용이 공식 룰북의 1개 제한보다 우선한다. 랭크 토큰은 카드당 한 개다.

Inquisitor는 일반 캐릭터 데이터와 분리한다. clan=Secret Order, rankToken=Fleur Cross, affiliations=Wild 2슬롯, clue=Rose 또는 Beast, ability=Curse Distribution이다. Wild 슬롯은 Rose, Beast, Unknown 세 토큰 종류 중 공급처에 남은 종류를 고를 수 있다. 같은 종류를 선택할 수 있는 횟수는 Wild 슬롯 수인 2회까지다.

## 5. 인원별 구성과 초기화

| 인원 | Rose | Beast | Inquisitor |
|---:|---:|---:|---:|
| 6 | 3 | 3 | 0 |
| 7 | 3 | 3 | 1 |
| 8 | 4 | 4 | 0 |
| 9 | 4 | 4 | 1 |
| 10 | 5 | 5 | 0 |
| 11 | 5 | 5 | 1 |
| 12 | 6 | 6 | 0 |

게임 설정에서 인원, 플레이어 이름, 좌석 순서, 좌석 방향, 난수 시드를 받는다. 각 클랜 9장을 시드 기반으로 각각 섞고 표의 수만큼 고른다. 홀수 게임에서는 Inquisitor 1장을 포함한다. 선택 카드를 다시 시드 기반으로 섞어 좌석에 배분한다. 동일한 시드, 입력 플레이어 순서, 코드 버전이면 캐릭터 선택·배분·시작 단검이 재현되어야 한다. 시작 단검은 무작위 플레이어 한 명에게 배분한다.

Inquisitor Curse 구성: 7명은 True 1/False 1, 9명은 True 1/False 2, 11명은 True 1/False 3이다. Curse 능력을 사용하면 Inquisitor만 공급처의 모든 Curse 앞면을 확인한 후, 자기 자신을 제외한 서로 다른 플레이어들에게 각각 한 장씩 뒷면으로 준다. 대상자는 게임 종료 때까지 Curse의 종류를 볼 수 없다. Curse 분배는 능력 사용 시 한 번만 가능하며, 배분 완료 후 재배분하지 않는다.

## 6. Clue 및 비공개 정보

게임 준비 후 각 플레이어는 자기 캐릭터의 Clue만 자기 왼쪽 이웃에게 보여준다. P의 Clue는 P의 왼쪽 이웃만 확인한다. 역할 확인과 Clue 확인은 별도 화면과 별도 권한으로 처리한다.

Pass-and-Play 전환 절차:

1. 현재 플레이어의 비공개 화면을 종료한다.
2. 캐릭터·Clue·Harlequin 열람 정보를 가린다.
3. “다음 플레이어에게 기기를 넘기세요” 화면을 보여준다.
4. 새 플레이어가 길게 눌러 자기 확인 절차를 시작한다.
5. 해당 플레이어에게 허용된 정보만 ViewModel에 포함해 보여준다.
6. 확인 종료, 시간 초과 또는 화면 이탈 시 즉시 다시 가린다.

정보 권한:

- 자기 캐릭터: 해당 플레이어만 확인
- Clue: 지정된 왼쪽 이웃만 확인
- Harlequin 열람 카드: Harlequin 능력 사용자만 확인
- 공개 토큰과 공개 능력 카드: 모두 확인
- Curse 종류: 게임 종료 전 누구도 확인할 수 없음. Inquisitor도 배분 완료 후에는 확인 불가
- 게임 종료 후: 모든 캐릭터와 Curse를 공개

UI에서 가리는 것만으로 보안을 처리하지 않는다. unauthorized fields 자체를 플레이어별 ViewModel에서 제외한다. Harlequin 열람 이력은 다른 플레이어의 ViewModel이나 공개 로그에 넣지 않는다.

## 7. 턴, 공격, 개입, 상처

단검 보유자가 액티브 플레이어다. 한 턴에 Attack 또는 Pass 하나를 선택한다. Pass는 다른 플레이어 누구에게나 넘길 수 있고 횟수 제한이 없다. 자동 패배·강제 종료·무한 루프 감지로 Pass를 막지 않는다.

Attack 절차:

1. 공격자가 자신이 아닌 유효 대상 한 명을 지정한다.
2. 대상이 Shield 보호 중이면 일반 공격은 불법이다.
3. Inquisitor는 이미 상처 3개인 플레이어를 일반 공격할 수 없다.
4. Fan 보유자가 공격 대상이면 개입 제안 단계를 생략한다.
5. 그 외에는 대상이 개입 여부를 요청할 수 있고, 랭크 토큰을 아직 공개하지 않은 플레이어만 공개적으로 개입 제안을 할 수 있다. 공격자와 대상은 개입할 수 없다. Shield 보유자는 개입할 수 있다.
6. 대상은 제안자 중 한 명을 선택하거나 모두 거절한다.
7. 개입이 수락되면 개입자가 원래 대상 대신 상처를 받으며 랭크 토큰을 반드시 공개한다. Shield는 이 개입 상처를 막지 않는다.
8. 실제 상처 대상의 토큰을 처리하고, 랭크 토큰을 새로 공개했다면 그 플레이어의 능력 사용 단계를 처리한다.
9. 모든 중첩 처리가 끝나고 게임이 계속되면 공격 상처를 실제로 받은 플레이어에게 단검을 전달한다. 개입자가 실제 상처 대상이면 개입자에게 전달한다.

상처 처리:

- 상처 0~2개 상태에서 상처를 받을 때 카드에 존재하는 아직 소진되지 않은 토큰 슬롯 하나를 선택해 공개한다. 대상 플레이어가 선택한다. 개입 상처는 랭크 토큰을 강제한다.
- 랭크 토큰은 카드의 랭크와 일치해야 한다. 랭크 토큰을 이미 가진 경우 다시 받을 수 없다.
- Mage Staff 보유자가 Affiliation 토큰을 선택하면 반드시 Unknown이어야 한다. Staff 효과가 해당 캐릭터의 실제 Affiliation 슬롯을 변경하지는 않는다.
- Inquisitor는 Wild 제한에 따라 Rose, Beast, Unknown을 선택한다.
- 현재 상처가 3개인 플레이어가 다시 상처를 받으면 네 번째 상처로 즉시 포획된다. 추가 토큰을 받지 않는다.
- 합법적인 토큰이 공급처에 없으면 게임을 임의 토큰으로 진행하지 않는다. 이 프로젝트의 토큰 수와 게임 인원에서 정상 구성상 발생하지 않아야 하며, 발생 시 엔진 오류 상태와 로그를 표시한다.

## 8. 능력 발동 및 중첩 처리 정책

능력 사용은 선택 사항이다. 플레이어가 상처로 랭크 토큰을 새로 공개한 직후 능력 사용 선택을 받는다. 이는 일반 공격, 개입, Assassin/Mentalist/Alchemist/Berserker 등 다른 능력으로 인해 발생한 상처 모두에 적용한다. 이 정책은 공식 룰북의 “공격 중 랭크 토큰을 얻은 직후” 조건을 확장한 디지털 구현 정책이다.

능력으로 발생한 상처는 새로운 공격으로 취급하지 않는다. 따라서 새 개입 절차는 없고, 공격 선언 효과, Fan, Inquisitor 일반 공격 제한도 재적용하지 않는다. 그러나 그 상처로 새로운 랭크 토큰이 공개되면 그 대상은 자기 능력 사용 여부를 선택할 수 있다. 중첩은 상처를 한 번 적용할 때마다 다음 순서로 해결한다.

1. 상처 적용 또는 네 번째 상처 포획 검사
2. 포획이면 즉시 전체 게임 종료
3. 포획되지 않았고 랭크 토큰을 새로 공개했다면 그 플레이어의 능력 선택 및 해결
4. 능력이 만든 상처가 있으면 해당 상처를 순차 적용하고 같은 규칙을 재귀적으로 처리
5. 현재 능력의 남은 효과를 이어서 처리
6. 포획되지 않았다면 원래 공격의 단검 전달

재사용 제한은 능력별 규칙을 따른다. 능력 처리 도중 포획되면 대기 중인 능력, 능력 효과, 단검 전달을 전부 취소한다. 능력 중첩은 엔진의 명시적 resolution stack으로 저장하여 순서와 로그가 재현 가능해야 한다. 무한 루프를 막기 위한 임의 횟수 제한을 게임 규칙으로 추가하지 않는다.

## 9. 캐릭터 능력 상세

### Elder (1) — Quill

Quill을 공급처에서 가져와 공개한다. Elder는 리더가 아니게 된다. 같은 클랜에서 Elder를 제외한 참가자 중 랭크 번호가 가장 큰 플레이어가 즉시 새 리더가 된다. Quill은 게임 동안 유지된다. 카드 공급처에 Quill이 없으면 능력을 사용할 수 없다.

### Assassin (2) — 강제 상처 2개

자신을 포함한 플레이어 한 명을 대상으로 선택할 수 있다. 대상에게 상처 2개를 순차 적용한다. 각 상처마다 포획 및 랭크 공개 능력을 처리한 뒤 다음 상처로 진행한다. 첫 번째 상처에서 포획되면 두 번째 상처를 취소한다. 두 상처 모두 처리된 뒤 대상이 살아 있으면 단검을 대상에게 준다. 대상의 Shield가 상처를 막으면 불법 대상이다.

### Harlequin (3) — 캐릭터 카드 2장 확인

Harlequin 자신을 제외한 서로 다른 두 플레이어를 선택한다. 카드 앞면은 Harlequin에게만 잠시 표시하고, 확인 후 즉시 뒷면 상태로 복구한다. 확인 사실과 내용은 공개 로그에 노출하지 않는다. 열람 정보는 능력 사용자만 볼 수 있고, 플레이어는 공개 토론에서 거짓말할 수 있다.

### Alchemist (4) — 상처 추가 또는 치유

Alchemist가 공격에 개입자로 선택되어 상처를 받은 경우에만 사용할 수 있다. 원래 공격 대상에게 상처 1개를 주거나, 그 대상의 공개 토큰 하나를 공급처로 돌려보내 상처 1개를 치유한다. 대상은 Alchemist 자신이 될 수 없다. Shield는 이 능력의 상처를 막지 않는다. 상처 추가로 포획되면 즉시 게임 종료한다. 랭크 토큰을 반환한 플레이어는 이후 다시 랭크 토큰을 상처로 공개할 때 능력을 다시 사용할 수 있다. 반환한 공개 토큰은 공급처에 복귀하고 같은 토큰 슬롯을 다시 사용할 수 있다.

### Mentalist (5) — 강제 상처 1개

자기 자신을 제외한 플레이어 한 명을 선택한다. Shield 보유자는 유효 대상이 아니다. 대상이 랭크 토큰을 가지고 있지 않으면 랭크 토큰을 강제로 가져간다. 이미 랭크 토큰이 있으면 아직 사용하지 않은 합법적 Affiliation 토큰 하나를 선택하게 한다. 대상의 현재 상처가 3개면 추가 토큰 없이 즉시 포획한다. 생존하면 단검을 대상에게 전달한다.

### Guardian (6) — Shield / Sword

자기 자신을 제외한 플레이어 한 명에게 공급처의 Shield를 주고, Guardian은 같은 pairId의 Sword를 받는다. 플레이어는 서로 다른 Guardian에게서 여러 Shield를 받을 수 있으며, Shield가 하나라도 남아 있으면 보호된다. 장비 재사용 시 기존 Shield/Sword를 회수하거나 이동하지 않고 새 장비를 추가한다. 공급처에 필요한 카드 쌍이 없으면 능력을 사용할 수 없다. Shield 보유자는 일반 공격과 능력에 의한 강제 상처 대상이 될 수 없지만 개입은 가능하고 개입 상처를 정상적으로 받는다. Alchemist의 상처 추가도 강제 상처이므로 Shield가 막는다. 연결된 Guardian이 세 번째 상처를 받으면 그 Guardian의 Sword와 그 pairId에 연결된 모든 Shield를 공급처로 돌려보낸다. 다른 pairId Shield는 유지된다.

### Berserker (7) — 반격

자신을 공격한 행위자에게 상처 1개를 강제한다. 이 상처는 새 공격이 아니며 개입을 발생시키지 않는다. 포획되면 Berserker를 포획 유발자로 기록하고 즉시 종료한다. 생존하면 Berserker는 원래 공격에서 상처를 받은 플레이어이므로 원래 공격 절차에 따라 단검을 받는다. 반격 능력 자체의 별도 단검 전달은 발생시키지 않는다.

### Mage (8) — Staff

자신을 제외한 플레이어 한 명에게 Staff를 주고 Mage 자신도 Staff를 받는다. 두 번째 및 이후 사용에서는 다른 플레이어에게 Staff를 추가로 줄 수 있지만 Mage는 Staff를 추가로 받지 않는다. 이미 Staff를 가진 플레이어도 공급처 카드가 있으면 추가 Staff를 받을 수 있으나 효과는 동일하며, 한 번의 토큰 선택에서 Unknown만 선택하면 된다. Staff 효과는 캐릭터의 실제 Affiliation 데이터와 별도 관리한다.

### Courtesan (9) — Fan

자기 자신을 제외한 플레이어 한 명에게 공급처의 Fan을 준다. Fan 보유자가 공격 대상이면 개입 요청을 하지 않는다. Fan은 공격 자체를 막지 않는다. 재사용할 때 기존 Fan은 회수하지 않고 공급처의 Fan을 추가 배분한다. 공급처에 Fan이 없으면 능력을 사용할 수 없다.

### Inquisitor — Curse Distribution

랭크 토큰을 상처로 새로 공개한 뒤 사용할 수 있다. 공급처의 Curse를 모두 확인하고, 자기 자신을 제외한 서로 다른 플레이어들에게 각 한 장씩 뒷면 배분한다. 수령자는 게임 종료까지 내용을 보지 못한다. 모든 Curse를 배분할 유효한 대상 수가 부족하면 능력 사용은 불법이다. 분배가 완료되면 게임 종료 때까지 재사용할 수 없다.

## 10. 포획 및 결과 판정 순서

네 번째 상처가 발생하면 다음 순서로 원자적으로 처리한다.

1. 포획 대상과 포획을 일으킨 행위자를 기록한다.
2. 진행 중인 능력 resolution stack과 미완료 단검 전달을 취소한다.
3. Inquisitor가 포획 대상이면 Inquisitor 단독 승리를 확정한다.
4. 모든 캐릭터를 공개한다.
5. 현재 Elder/Quill 상태를 반영해 Rose와 Beast 리더를 계산한다.
6. 행위자 클랜과 포획 대상/리더 관계로 일반 승리 클랜을 판정한다.
7. Curse를 공개하고 True Curse의 승리 클랜 리더 소지 여부를 검사한다.
8. Inquisitor 덮어쓰기와 최종 승자를 기록한다.
9. 게임 종료 이벤트와 결과 화면을 제공한다.

포획 후에는 어떤 게임 행동도 허용하지 않는다. 결과 화면은 엔진이 만든 VictoryResult만 표시한다.

## 11. 상태 관리 및 게임 단계

상태 머신은 최소한 다음 단계를 구분한다. 필요한 세부 능력 단계는 추가할 수 있지만 새 게임 규칙은 추가하지 않는다.

TITLE, PLAYER_SETUP, CHARACTER_DISTRIBUTION, ROLE_REVEAL, CLUE_REVEAL, TURN_START, ACTION_SELECTION, ATTACK_TARGET_SELECTION, INTERVENTION_REQUEST, INTERVENTION_SELECTION, WOUND_RESOLUTION, TOKEN_SELECTION, ABILITY_DECISION, ABILITY_RESOLUTION, DAGGER_TRANSFER, NEXT_TURN, CAPTURE_RESOLUTION, GAME_END.

각 단계에서 허용되는 Action을 엔진이 검증한다. 불법 대상, 자기 공격, 보호 대상 공격, 잘못된 토큰, 이미 종료된 게임 행동, 허용되지 않은 비공개 데이터 접근은 오류 결과를 반환하고 상태를 변경하지 않는다. 모든 상태 변경은 불변성 유지. 로그는 재현 가능하고 공개/비공개 가시성을 가진다.

## 12. UI 및 시각 디자인

화면: 타이틀, 게임 설정, 역할 확인, Clue 확인, 메인 보드, 턴 행동, 능력별 입력, 종료 결과, 검색 가능한 도움말/룰북.

메인 보드는 원형 좌석 배치다. 이름, 공개 랭크/affiliation 토큰, 상처 수, Shield/Sword/Staff/Fan/Quill, 단검 보유를 표시한다. 캐릭터의 비공개 정체는 게임 종료 전 노출하지 않는다.

디자인은 고딕 판타지, 로코코 장식, 뱀파이어 가면무도회 분위기의 독창적인 SVG 문양과 실루엣을 사용한다. 원작 아트나 상표 로고를 복제하지 않는다. Rose는 진홍/로즈골드/장미/가시, Beast는 짙은 청록/호박색/발톱/늑대, Secret Order는 보라/은색/팔각 문양으로 표현한다. 색상 외에 아이콘 형태와 문양으로도 진영을 구분한다.

카드 플립, 토큰 낙하, 단검 이동, 상처 흔들림, 능력 발동, 리더 변경, 종료 애니메이션을 구현한다. 모션 감소 설정을 지원한다. 모바일 세로 화면 우선, PC 반응형, 최소 44px 터치 영역, 텍스트 대비 4.5:1 이상, 글씨 크기 설정, 키보드 접근성을 지원한다. 디자인 토큰은 CSS 변수로 관리한다.

## 13. 필수 테스트

규칙 엔진 테스트는 UI 없이 실행 가능해야 한다. 최소 다음을 테스트한다.

1. 6~12명 카드 구성
2. 동일 시드 셔플 재현성
3. 초기 리더 계산과 Quill 후 리더 변경
4. 캐릭터별 Affiliation 적법성
5. 중복 Affiliation 토큰 허용/초과 거부
6. 네 번째 상처 포획 및 토큰 생략
7. 개입 조건, 개입 시 랭크 공개, Shield 보유자 개입
8. Guardian Shield 공격/강제 상처 차단, 개입 상처 허용
9. Guardian 세 번째 상처 장비 회수 및 pairId 격리
10. Alchemist 치유, 랭크 반환 후 능력 재사용
11. Mentalist 랭크 강제 공개와 포획
12. Assassin 첫 상처 및 두 번째 상처 포획
13. Berserker 반격 및 반격 포획자 기록
14. Mage Staff의 Unknown 강제와 재사용
15. Courtesan Fan의 개입 단계 생략
16. Inquisitor 인원별 Curse 구성, Wild 토큰, 자기 Curse 배분 금지
17. Inquisitor 직접 포획 승리 및 True Curse 승리 가로채기
18. 무제한 Pass와 불법 행동 거부
19. 플레이어별 비공개 ViewModel과 Harlequin 열람 정보 보호
20. 종료 후 행동 차단 및 공개/비공개 로그 분리
21. 중첩 능력 순서와 포획 즉시 처리 중단

통합 테스트는 최소 게임 생성부터 종료 판정까지 한 번의 재현 가능한 시나리오를 검증한다.

## 14. 수동 테스트 시나리오

최종 보고에 다음 10개 수동 테스트를 포함하고 실제 실행 결과를 기록한다.

1. 7인 게임에서 Inquisitor가 포획되어 단독 승리
2. Guardian Shield 보호 중 일반 공격 시도 거부
3. Alchemist 치유로 랭크 토큰 반환 후 재공개 시 능력 재사용
4. Mentalist 능력으로 네 번째 상처 및 포획
5. Assassin 첫 번째 강제 상처에서 포획되어 두 번째 상처 취소
6. Berserker 반격으로 공격자가 포획되고 Berserker가 포획자로 기록
7. Elder의 Quill 사용 후 최고 랭크 번호 참가자로 리더 변경
8. Harlequin이 자기 자신을 제외한 두 역할을 비공개 확인
9. 중복 Affiliation 슬롯의 토큰 두 개 허용 및 세 번째 거부
10. 게임 종료 후 전 캐릭터와 Curse 공개, 이후 Action 거부
