# 구현 결정

- 기존 게임과 같은 Render/Docker 진입점을 사용하기 위해 `hushfall/`에 독립 Vite 앱을 두고 단일 Node WebSocket 프로세스로 방을 관리한다.
- 60Hz 호스트 시뮬레이션을 사용한다. 연결되는 동안 WebSocket으로 플레이할 수 있고, WebRTC가 준비되면 입력과 스냅샷을 비순서·비재전송 DataChannel로 전송한다. 방·확정 이벤트·결과는 WebSocket을 사용한다.
- 현재 형식은 압축한 전체 스냅샷이다. 탄막 이벤트 재현 없이도 게스트의 새로고침과 이동 중 상태 복구가 가능하다.
- 이전 세션과 구별하기 위해 온라인 방의 시드를 런 ID로 사용한다. 솔로는 새 런에 별도 ID를 발급해서 재개와 결과 정산을 연결한다.
- 다섯 기체는 같은 프리셋을 두 자리에서 사용할 수 있다. 초기 해금은 저장된 Stardust 문턱에 연결한다.
- 타이틀 일러스트와 기체·탄막 도형을 직접 그렸다. 효과음은 WebAudio로 합성하고 글자는 시스템 폰트 스택을 사용한다.
- 오늘의 항해는 UTC 날짜를 시드로 쓰는 첫 구역 챌린지다. 무한 이후 구역은 기존 테마를 순환하면서 난이도를 올린다.
- 난이도 비교가 가능하도록 Calm과 Heat 1–10을 바로 고를 수 있게 했다. Daily에서는 Calm을 제외한다.
- 보스 정면의 밝은 코어에 완전 피해를 적용하고, 페이즈별 수평 이동으로 조준과 회피를 번갈아 요구한다.
- 재정비가 시작되면 이전 편대와 적탄을 정리한다. 드래프트를 읽는 동안 탄막보다 남은 선택 시간이 주된 제한이 된다.
- 첫 강화에서 화력·제어·보호를 고를 수 있게 하고, 이후에는 우선순위 재료 한 장과 일반 후보 두 장을 섞었다. 진화 조건은 첫 구역에서도 도달할 수 있도록 조정했다.
- 새 스냅샷 필드와 강화 우선순위 명령을 도입하며 방 프로토콜을 2로 올렸다. 기존 솔로 체크포인트는 추가 상태의 기본값으로 복구한다.
