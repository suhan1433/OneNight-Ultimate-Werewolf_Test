# LUMEN TETHER (루멘 테더) — 마스터 개발 프롬프트 v1.0

> 게임 디자인 바이블 + 구현 명세. 이 문서 전체를 코딩 에이전트의 초기 프롬프트로 붙여 넣는다. 컨텍스트가 부족하면 PART 0\~1은 항상 유지하고 나머지는 PART 13의 Phase 매핑표대로 필요한 파트만 추가한다. 모든 수치는 1차 밸런스 초안이며 반드시 데이터 파일에서 조정 가능해야 한다. LUMEN TETHER는 작업명이므로 출시 전 상표·도메인 검색을 할 것.

## PART 0. 에이전트 역할과 작업 규칙

너는 시니어 게임 클라이언트·네트워크 엔지니어이자 게임 디자이너다. 아래 명세의 게임을 **즉시 출시 가능한 품질**의 웹앱(PWA)으로 구현한다.

1. 질문하지 않는다. 명세에 없는 사항은 장르 관례와 모바일 우선 원칙으로 결정하고 `DECISIONS.md`에 이유를 한 줄씩 기록한다.
2. 플레이스홀더, TODO, 더미 데이터 금지. 매 Phase 종료 시점에 항상 실행 가능한 빌드를 유지한다(타입체크·린트·테스트 통과).
3. 모든 콘텐츠(적, 탄막 패턴, 카드, 유물, 스테이지, 밸런스 수치)는 코드가 아니라 `src/data/`의 데이터로 정의한다(데이터 주도).
4. 에셋 리스크 제거: 그래픽은 벡터·프로시저럴, 사운드는 WebAudio 합성, 폰트는 OFL 라이선스만 사용한다. 기존 게임의 캐릭터·명칭·에셋은 복제하지 않는다(메커닉만 참고).
5. 성능 예산, 접근성, 저장 무결성은 부가 기능이 아니라 합격 조건이다.
6. 각 Phase 종료 시 보고한다: 구현 목록 / 미구현·위험 / 측정치(FPS, 번들 크기, 네트워크 지연) / 다음 계획.
7. 명세가 충돌하면 숫자가 명시된 쪽, 그다음 뒤쪽 파트를 우선한다.

## PART 1. 제품 개요

### 1.1 한 줄 피치

빛의 끈(Tether)으로 이어진 두 조종사가 꺼져가는 별자리를 지키며 공허의 파도를 뚫고 내려가는, **자동 공격 + 좌우 이동** 로그라이트 종스크롤 슈터. 솔로 / 온라인 2인 / 로컬 2인.

### 1.2 플랫폼과 세션

- 모바일 세로 화면 우선(iOS Safari, Android Chrome), 데스크톱 브라우저 동시 지원. PWA 설치와 오프라인 솔로 플레이 지원.
- 한국어·영어 동시 출시. i18n 구조는 일본어·중국어를 나중에 추가할 수 있게 한다.
- 세션 길이: Voyage 1판 18\~25분, Endless·Daily 6\~12분. 앱 전환·탭 비활성·전화 수신 등 모든 중단 상황에서 자동 일시정지되어야 한다.

### 1.3 핵심 재미 3가지

1. **한 손 조작 + 자동 공격**: 진입장벽은 낮고 승부는 이동과 선택에서 갈린다.
2. **30\~40초마다 오는 빌드 선택**: 카드·진화·원소 조합으로 매 판 다른 빌드가 나와 한 판 더를 부른다.
3. **둘이어서 생기는 시너지**: Tether 거리 줄다리기, 원소 공명, 듀엣 버스트, 부활.

## PART 2. 세계관·아트·오디오 디렉션

### 2.1 세계관 (텍스트 최소, 연출로 전달)

별자리가 하나씩 꺼지고 있다. 원인은 모든 빛을 삼키는 존재 **정적(The Hush)**. 등불을 든 **루멘 파일럿** 두 명이 빛의 끈으로 기체를 이어 5개 성역을 내려가 정적의 심장에 불을 켠다. 대사는 없고 스테이지 시작 시 한 줄 카피와 아이콘 연출만 쓴다.

### 2.2 비주얼: 네온 벡터 + 심해 같은 남색 우주

- 팔레트(`theme.ts` 단일 출처): 배경 #070B1A → #14204A / P1 #3CE6FF / P2 #FFD84A / 적 탄 코어 #FFFFFF + 림 #FF3D8B·#FF8A3D / Tether 흰색 → 두 기체 색 그라디언트 / 원소 화염 #FF6A3D, 빙결 #8FE3FF, 전격 #B58CFF, 중력 #5CFFB0 / 경험치 젬 #5AA8FF / 샤드 #F5F0C8
- **가독성 규칙(합격 조건)**
  1. 적 탄은 항상 최상위 레이어, 흰 코어 + 채도 높은 림. 아군 탄은 알파 0.7 이하의 가는 형태.
  2. 파티클·글로우는 탄 아래 레이어. 전체 화면 플래시는 최대 알파 0.25, 설정으로 끌 수 있다.
  3. 피격 판정 코어(반경 6px)는 항상 표시한다.
  4. 탄 종류는 색뿐 아니라 모양(원, 마름모, 바늘, 링)으로도 구분한다.
  5. 보스 탄막은 발사 0.6초 전에 발사 지점을 하이라이트(텔레그래프)한다.
- 렌더 레이어(아래 → 위): 배경 3겹 → 지상 장식 → 드롭 → 적 → 아군 탄 → 플레이어·Tether → 파티클 → 적 탄 → 데미지 숫자 → HUD(DOM)
- 품질 티어 Low / Medium / High: 최근 10초 프레임타임으로 자동 판정하고 설정에서 수동 변경 가능. 블룸, 파티클 상한(150/400/900), 배경 레이어 수(1/2/3), 데미지 숫자 표시 여부가 달라진다.
- 기체·적·UI 아이콘은 모두 코드로 그린 벡터 도형이며 시작 시 텍스처 아틀라스로 베이크한다. 외부 이미지 에셋은 0개.

### 2.3 오디오: 100% WebAudio 합성

- 음악: 스테이지별 프로시저럴 루프(BPM 110 / 118 / 126 / 132 / 140), 보스 전용 루프 1개. 베이스·리듬·리드 레이어를 콤보 구간, Overdrive, 보스 페이즈에 따라 페이드 인.
- SFX 약 30종: 발사(피치 ±3% 랜덤), 적 피격, 처치, 그레이즈 틱(콤보에 따라 음계 상승), 피격, 레벨업 아르페지오, 카드 선택, 대시, Nova, Duet, 부활, 보스 경고, 페이즈 브레이크.
- 믹스 규칙: 동시 발음 24개 제한, 같은 SFX는 30ms 안에 중복 재생 금지, 보스 경고 시 음악 ducking −8dB. 첫 사용자 제스처에서 AudioContext를 resume하고 iOS 무음 모드·백그라운드 복귀 처리를 구현한다.
- 설정: 마스터·음악·효과음 3 슬라이더, 진동 on/off.

## PART 3. 코어 게임플레이

### 3.1 플레이필드

- 논리 해상도 **540×960 (9:16)**. 렌더 해상도는 DPR 상한 2(Low 티어는 1.5). 데스크톱은 중앙 세로 플레이필드 + 좌우 패널(파트너 상태, 내 빌드 요약).
- 플레이어는 **Y=820 고정, X는 30\~510** 범위에서 좌우로만 이동한다. 적은 y=−60에서 스폰, 탄은 화면 밖 80px에서 소멸한다.
- 배경은 3겹 패럴랙스(60 / 120 / 220 px/s)이며 스테이지마다 테마가 다르다.
- **고정 타임스텝 60Hz 시뮬레이션 + 보간 렌더**. 시뮬레이션은 렌더·DOM과 분리되어야 하고(헤드리스 실행 가능), 탭 비활성 시 자동 일시정지한다.

### 3.2 조작

| 입력 | 이동 | 스킬1 (대시) | 스킬2 (Nova / Duet) | 일시정지 |
| --- | --- | --- | --- | --- |
| 터치 | 하단 60% 영역 상대 드래그(민감도 0.8\~1.6, 기본 1.15) | 더블탭 또는 좌하단 버튼 | 우하단 버튼 | 우상단 아이콘 |
| 키보드(솔로·온라인) | A/D 또는 ←/→ | Space | Shift 또는 E | Esc, P |
| 키보드(로컬 2P) | P1: A/D, P2: ←/→ | P1: W, P2: ↑ | P1: S, P2: ↓ | Esc |
| 게임패드 | 좌스틱 / D-pad | A | X 또는 RT | Start |

- 이동은 80ms 가속 보간. 입력 버퍼 100ms. 좌·우손잡이 버튼 배치 반전 옵션 제공.
- 터치 드래그는 상대 이동이라 손가락이 기체를 가리지 않는다. 손가락을 떼면 즉시 정지.

### 3.3 자동 공격

- 공격은 항상 자동이다. 기본은 전방 직선 발사, 호밍 계열만 최근접 적을 조준한다.
- 표준 스탯: Atk(공격력), Rate(초당 발사 횟수), 탄속, 관통, 크리티컬(확률·배율 기본 ×1.8), 범위. 모든 카드·유물은 이 스탯과 태그만 수정한다.

### 3.4 생존과 부활

- **Hull(체력 칸)**: 기체별 3\~5칸. 일반 탄·접촉 1칸, 중탄·레이저·보스 슬램 2칸.
- 피격 시 무적 1.4초 + **Mercy Pulse**(반경 120px 안의 일반 탄 제거). 같은 프레임의 다중 피격은 1회로 처리한다.
- **Lumen Shield**: 1회 피해 무효, 재충전 14초(카드로 단축). 피격 시 재충전 타이머 리셋.
- **쓰러짐(Wreck)**: Hull 0이 되면 기체가 잔해로 12초간 떠 있다. 파트너가 겹쳐서 2.0초 머물면 부활(Tether 링크 중에는 1.2초), 부활 시 Hull 2 + 무적 2초. 12초 안에 부활하지 못하면 해당 막이 끝날 때까지 이탈하고 다음 막에서 Rescue Beacon으로 복귀한다.
- **Rescue Beacon**: 팀 공유 부활권, 런 시작 시 2개(솔로는 1개 + 드론). 둘 다 동시에 쓰러지거나 Beacon이 없는 상태에서 쓰러지면 런 종료.

### 3.5 스킬

- **Dash**: 0.22초, 이동 거리 170px, 무적 0.22초, 쿨타임 6초.
- **Nova Burst(궁극기)**: 게이지 100%에서 사용. 게이지는 처치 +1, 그레이즈 +0.5, 엘리트 처치 +8. 효과: 화면 내 일반 탄 전부 소거 → 샤드로 변환, 모든 적에게 Atk×30 피해(보스는 최대 체력의 3% 상한), 1.0초 무적.
- **Overdrive**: 그레이즈로 쌓이는 별도 게이지(그레이즈당 +1.5, 100에서 자동 발동). 8초 동안 공격속도 +40%, 그레이즈 점수 ×2.

### 3.6 Tether — 이 게임의 핵심 메커닉

두 기체 사이의 거리가 **260px 이하**이면 링크가 활성화된다(카드로 최대 380px). 링크되면 두 기체 사이에 빛의 실이 아치 모양으로 올라가고, 그 아래 **Tether Field**(두 기체 사이 폭 × 높이 240px, y 580\~820 구간)가 생긴다.

| 링크 효과 | 값 |
| --- | --- |
| 공격속도 | 두 기체 모두 +10% |
| Field 안의 적 | 0.25초 틱으로 초당 Atk×1.0 피해, 이동속도 −20%(엘리트 −10%, 보스 면역) |
| Resonance 게이지 | 초당 +4, 처치당 +1, Tether Spark 픽업 +10 |
| 상호 보호 | 쉴드 재충전 시간 −20% |
| 부활 | 필요 시간 2.0초 → 1.2초 |

- **Resonance 100**이 되면 **Duet Burst**를 쓸 수 있다. 두 사람이 1.0초 안에 Burst 입력을 하면 두 기체 사이에서 거대한 빔이 위로 스윕한다(Atk×60 피해, 탄 소거, 원소 공명 효과 확장). 한쪽만 누르면 1.0초 대기 후 일반 Nova로 전환된다.
- **긴장 구조**: 붙어 있으면 버프와 부활이 빠르지만 같은 광역 탄에 함께 노출된다. 떨어지면 커버 범위가 넓어지고 안전하지만 버프를 잃는다. 이 줄다리기가 협동의 재미다.
- 링크 유지 시간은 점수(초당 100점)와 업적에 반영한다. 링크가 끊길 때 사운드·진동으로 즉시 피드백한다.

### 3.7 원소와 공명 콤보

원소 4종(화염·빙결·전격·중력)은 카드에 태그로 붙고, 두 사람의 보유 원소 조합이 공명을 만든다. 각 플레이어의 주 원소는 해당 원소 카드의 보유 레벨 합이 가장 큰 쪽으로 자동 판정하며, 공명은 두 사람 모두 해당 원소 레벨 합이 3 이상일 때 활성화된다.

| 조합 | 공명 이름 | 효과 |
| --- | --- | --- |
| 화염 + 빙결 | 증기 장막 | Field를 통과하는 적 탄 속도 −30%(1.5초) |

### 3.8 점수

- 처치 점수 = 적 기본 점수 × **Combo**. Combo = 1 + 0.04 × chain(최대 ×5.0, chain 100). 2.5초 동안 처치가 없으면 chain 50% 감소, 피격 시 50% 감소.
- **그레이즈**: 적 탄이 코어 16px 이내를 지나가면 탄 1개당 1회 +25 × Combo, Overdrive +1.5.
- 스테이지 클리어 보너스: 시간 보너스(목표 시간 대비) + Perfect(Hull 손실 0) 50,000 + Link 보너스(링크 초 × 100) + 보스 격파 점수.
- 코옵에서는 팀 점수를 공유하고 개인 기여도(처치, 그레이즈, 링크, 부활, 피해 흡수)를 따로 집계해 결과 화면에 MVP를 표시한다.

## PART 4. 로그라이트 루프와 보상 설계

### 4.1 런 구조 (Voyage)

Stage 1\~5를 연속으로 플레이한다. 한 Stage의 흐름은 다음과 같다.

`Act 1 (80s) → Lull (8s) → Act 2 (80s, 엘리트 1) → Lull (8s) → Boss (60~100s) → Clear → 유물 3택 → Gateway(경로 선택 · Drifter 상점 · 이벤트) → 다음 Stage`

- Stage 1개는 4\~5분, Voyage 전체는 20\~23분. 각 Stage 시작이 자동 저장 체크포인트다(솔로).
- **Lull**: 적 스폰이 거의 없는 8초 안전 구간. 쌓인 레벨업 드래프트를 이 구간에서 소화한다.
- **Gateway 경로 선택**
  - Calm Route: 기본 보상.
  - Void Route: 다음 Stage 적 HP +15%, 엘리트 +1, 클리어 시 유물 선택지에 Epic 이상 1장 보장 + 샤드 +50%.
  - 코옵에서 두 사람의 선택이 다르면 5초 안에 핑으로 합의하고, 합의가 없으면 무작위 결정(Split Bonus: 샤드 +20).
- **Gateway 이벤트**(확률 20%, Stage 2\~4): ① Void Gate — 저주 1개를 받고 Epic 유물 보장 ② 난파선 — 샤드 대량 + 추가 웨이브 1회 ③ 수호 샘 — Hull 완전 회복 또는 즉시 레벨업 중 택1.

### 4.2 레벨업 드래프트

- XP는 **팀 공유**다. 누가 젬을 먹든 공유 바가 차고, 레벨업하면 **두 사람 모두** 각자 드래프트를 1회 받는다.
- 필요 XP: `xpToNext(L) = round(30 × 1.12^(L-1))`. 목표 케이던스: 첫 레벨업 ≤ 25초, Stage당 5\~7회, Voyage 종료 시 Lv 28\~32. 적의 `xpValue`는 이 케이던스에 맞춰 조정한다.
- 3장 제시. 희귀도 기본 확률은 Common 58 / Rare 28 / Epic 11 / Legendary 3(%)이며 Stage가 오를 때마다 Common −4, Rare +2, Epic +1.5, Legendary +0.5. Luck 수치는 Rare 이상 가중치에 곱해진다.
- 리롤 런당 2회, 밴(해당 런에서 영구 제외) 1회. Hangar로 확장한다.
- 슬롯: 서브 무기 4칸, 패시브 8칸. 슬롯이 차면 이미 보유한 카드의 강화만 제시한다.
- **비차단 규칙**: 드래프트는 Lull에서 소화한다. 대기 드래프트가 3개 이상 쌓이면 Draft Break(0.15× 슬로 모션, 최대 10초). 제한 시간(Lull 8초)을 넘기면 자동 선택(보유 카드 강화 우선, 없으면 첫 번째). 솔로는 설정에서 Classic Pause(레벨업 즉시 일시정지)를 켤 수 있다.
- 진화 조건을 충족하면 다음 드래프트에 진화 카드가 **반드시 1장 포함**된다(금색 프레임).

### 4.6 Drifter 상점 (Gateway)

- 샤드는 **개인 지갑**(자기가 먹은 만큼)이며 파트너에게 기부할 수 있다.

- 샤드 기대 획득량은 Stage당 220\~300. 한 번 방문에 2\~3개를 살 수 있는 수준으로 맞춘다.

### 5.3 탄막 패턴 DSL과 공정성 규칙

- 패턴 종류: `aimed`, `fan`, `ring`, `spiral`, `wall(gap)`, `rain`, `laser(telegraph)`, `homing(slow)`, `bounce`. 모든 패턴은 데이터로 정의하고 코드를 새로 쓰지 않는다.

```ts
export const mothFan: PatternDef = {
  id: 'moth_fan',
  telegraph: 0.6,
  emit: [{ t: 0, kind: 'fan', count: 7, spreadDeg: 60, speed: 170, bullet: 'orb_m', aim: 'nearest' }],
  repeat: { every: 1.4, alternate: { speedDelta: 30 } },
};
```

- **해결 가능성(Solvability) 규칙**
  1. 벽 패턴 갭 폭은 Stage 1\~2에서 ≥ 110px, Stage 3\~5에서 ≥ 96px.
  2. 모든 벽·레이저는 텔레그래프 ≥ 0.6초.
  3. 갭 도달 조건: `|gapX − playerX| ≤ (timeToImpact − 0.25) × moveSpeed`를 모든 시점에서 만족하는 플레이어 위치가 항상 하나 이상 존재해야 한다(대시 없이도 성립).
  4. 동시 활성 레이저 ≤ 2, 연속 벽 사이 간격 ≥ 0.9초.
- **탄 밀도 예산(동시 탄 수)**: Stage 1 ≤ 120 / 2 ≤ 200 / 3 ≤ 300 / 4 ≤ 400 / 5 ≤ 500, 보스 순간 최대 700. 시뮬레이션 상한 700은 렌더 품질 티어와 무관하게 고정한다(공정성·넷코드 일관성).
- 자동 검증: 헤드리스 봇이 모든 패턴을 1,000개 시드로 시뮬레이션해 회피 가능성을 확인한다. CI 필수 통과 항목이다.
- 코옵에서 조준탄은 두 플레이어를 교대로 조준하고, 동일 패턴의 탄 수는 늘리지 않는다.

### 5.5 보스 5종 (HP는 Normal 솔로 기준. 코옵은 ×1.85)

공식: 보스 HP = 목표 DPS × 75초 × 0.85. 모든 보스는 입장 연출 4초(무적), 페이즈 전환 시 1.5초 무적과 탄 소거, 처치 시 0.3× 슬로 1.2초 연출을 가진다.

**보스 1. 어미나방 (HP 3,800)**

- P1 (100\~66%): 윙 더스트 — 좌우 날개에서 7발 부채꼴(속도 170)을 1.4초 간격으로, 8초마다 드리프터 4기 소환.
- P2 (66\~33%): 등불 사냥 — 1.0초 레인 텔레그래프 후 좌우 돌진, 돌진 후 3초마다 갭 1개 가루 벽(갭 130px, 속도 140).
- P3 (33\~0%): 광란 — 3팔 나선(회전 90°/s, 속도 150) + 2.5초마다 조준 3점사. 10% 이하에서 소형 나방 8마리(HP 20) 소환.
- 코옵: 링크 중이면 Tether 빛에 이끌려 중앙으로 이동해 Field 피해를 더 받는다(×1.5). 링크가 끊기면 한 명에게 조준을 집중한다.
- 보상: 유물 3택(Common\~Rare), Stardust 120.

**보스 2. 말미잘 여왕 (HP 7,000)**

- 구성: 본체 + 좌우 가장자리 촉수 2개(각 HP 1,500). 촉수가 살아 있으면 본체는 피해 −80%.
- P1: 촉수 스윕(텔레그래프 0.8초), 본체는 12방향 포자 링을 2초 간격으로 발사.
- P2: 촉수 파괴 후 12초 뒤 재생. 포자 구름 소환, 화면 하단 좌/우 1/3 독안개를 5초 예고 후 번갈아 활성.
- P3: 촉수 4개 동시 + 가시 비(갭 2개 벽).
- 코옵: 촉수는 Field 안에서 받는 피해 ×2. 분리해서 한 명이 한쪽 촉수를 전담할 수도 있다.
- 보상: 유물 3택(Rare 이상 1장 보장), Stardust 160.

**보스 3. 닻 거신 (HP 12,100)**

- P1: 닻 낙하 — 1.0초 텔레그래프(폭 80) 후 낙하, 충격파가 낮은 탄 벽으로 좌우 확산(대시 무적으로 통과 가능). 5초마다 유도 미사일 4발.
- P2: 좌우 포대 2기(각 HP 2,500)가 세로 레이저를 스윕(텔레그래프 1.0초) + 기뢰 살포.
- P3: 코어 노출(보스 HP 40% 구간), 전방위 링 탄 + 닻 2개 동시 낙하(갭 ≥ 140px).
- 코옵: 닻 충격파가 Tether를 끊는다(4초간 링크 불가). 재링크 성공 시 Resonance +20 보너스(회복 인센티브).
- 보상: 유물 3택(Rare 이상), Stardust 220.

**보스 4. 프리즘 성가대 (HP 19,000)**

- 구성: 좌 수정(4,500) / 중앙 수정(8,000, 보호막) / 우 수정(4,500).
- P1: 좌·우 수정이 1.0초 텔레그래프 후 레이저를 쏘고 중앙 수정이 반사해 대각 빔 2개를 만든다.
- P2: 좌·우 수정 파괴(파괴 시 폭발 탄), 중앙 수정이 4방향 굴절 링을 발사.
- P3: 중앙 수정이 미니 프리즘 6개로 분열, 반사 빔 격자(다이아몬드 패턴, 이동 레인 폭 ≥ 110px 유지).
- 코옵 **굴절 창**: 적 빔이 Tether Field 윗변을 지나면 반사되어 보스 수정에 큰 피해(Atk×15). 링크 거리와 위치로 빔을 받아내는 퍼즐 요소.
- 보상: 유물 3택(Epic 1장 보장), Stardust 300.

**보스 5. 정적 The Hush (HP 28,700)**

- 공통 **Dim**: 화면이 서서히 어두워지고 기체 주위 반경 220px만 밝다. 링크 중에는 두 기체 사이 Field 전체가 밝아진다. 단, 적 탄은 항상 림 하이라이트로 보여야 한다(가독성 규칙 유지).
- P1 (100\~60%): 정적의 손 — 좌우 상단에서 거대한 손이 번갈아 내려찍음(텔레그래프 1.2초, 충격 링). 그림자 소환.
- P2 (60\~25%): 소거 — 3분할 구역 중 2곳이 5초 예고 후 공허 구역(지속 피해)으로 바뀌어 이동을 강제. 공허 징병관 소환. HP 40% 지점에서 쉴드 단계: Duet Burst(솔로는 Nova 3회)로만 깰 수 있다.
- P3 (25\~0%): 점등 — 앞선 모든 패턴의 합성 + 4팔 나선 + 갭 벽. 마지막 10%는 탄속 ×0.7·밀도 ×1.4의 느리고 빽빽한 탄막(희망 연출, 해결 가능해야 함).
- 엔딩: 두 기체가 심장에 불을 켜는 연출 → 결과 화면 → Endless 해금 안내, 크레딧.
- 보상: Stardust 500, 칭호, 업적 First Light, 코스메틱 해금.

### 5.6 Endless: Abyss (무한 심연)

- **해금**: Voyage Stage 2 클리어. 시작 시 기체 선택 + Prelude(시작 원소 3택), 카드는 Lv0에서 시작.
- **구조**: Floor 1개 = 90초(엘리트 1체 포함). 5층마다 보스(5종 순환 + Void-touched 변형), 3층마다 Gateway(Drifter 상점 + 저주·축복 3택).
- **스케일링**: 적 HP ×1.16^floor(floor ≤ 25), 이후 추가로 ×1.06^(floor−25). 탄속 +1.2%/floor(상한 +40%). 스폰 예산 +4%/floor(상한 +150%). floor 40부터 모든 적에게 보호막(정적의 메아리).
- **보상**: Stardust = floor × 8 + 보스 보너스 100. 점수에는 floor 보너스 × (1 + 0.05 × floor)가 곱해진다.
- **마일스톤**: 10 / 20 / 30 / 50층에 코스메틱과 칭호 해금.
- **목표 분포**: 중급 플레이어 floor 10\~15, 상급 25+, 최상위 40+.
- 시뮬레이션 수치 오버플로를 막기 위해 HP·피해 계산은 부동소수 64bit로 하고 표시용 숫자는 K/M 단위로 축약한다.

## PART 6. 난이도와 밸런스 시스템

### 6.1 난이도 선택

- **Calm**: Hull +2, 탄속 −20%, 적 HP −15%, 점수 ×0.5, Stardust ×0.6, Daily·Weekly 제외. 입문자·어린이·여유롭게 즐기고 싶은 유저용이며 비하하는 표현을 쓰지 않는다.
- **Normal (Heat 0)**: 기준 난이도.
- **Void Heat 1\~10**: Normal 클리어 시 Heat 1 해금, Heat N 클리어 시 N+1 해금. 효과는 누적된다. Stardust 배율 = 1 + 0.12 × Heat.

| Heat | 추가 효과 |
| --- | --- |
| 1 | 적 HP +10% |
| 2 | 적 탄속 +6% |
| 3 | Stage당 엘리트 +1 |
| 4 | Repair 드롭 −40% |
| 5 | 보스 P2·P3에 변형 패턴 1개씩 추가 |
| 6 | 적 스폰 +15% |
| 7 | 쉴드 재충전 +4초 |
| 8 | Lull 8초 → 5초 |
| 9 | 보스 HP +20%, 탄속 +6% |
| 10 | 시작 Hull −1, 모든 적이 10% 확률로 Void-touched(보호막) |

### 6.2 코옵 스케일링

- 일반 적 HP ×1.6, 스폰 수 ×1.25, 보스 HP ×1.85. 탄 밀도는 늘리지 않고 조준탄이 두 플레이어를 교대로 노린다.
- XP·샤드 획득 규칙은 동일. Stardust 보상은 코옵 보너스 ×1.15.
- 한 명이 쓰러져 있는 동안 보스·엘리트 HP 증가분은 일시적으로 ×0.85로 완화한다(역전 가능성 확보).

### 6.4 스탯·데미지 공식

- `enemyHP = baseHP × stageMul[stage] × (1 + 0.02 × actIndex) × heatHpMul × coopHpMul`
- `damage = Atk × atkMul × (crit ? critMul : 1) × elementMul`
- **합산 규칙**: 같은 스탯에 대한 보너스는 **가산**, 서로 다른 계열(Atk, Rate, Crit, Element) 사이는 **승산**. 폭주를 막기 위한 하드 캡: Rate ≤ 기본 ×3.0, 이동속도 ≤ +60%, 쿨타임 감소 ≤ 60%, 크리 확률 ≤ 75%, Luck ≤ 100.
- 모든 확률·수치는 `data/balance.json` 한 곳에서 조정하고, 변경 시 `balanceVersion`을 올려 저장 데이터와 Daily seed에 반영한다.

### 6.5 밸런스 검증 도구 (필수 산출물)

- `tools/balance-bot`: 헤드리스 시뮬레이션 + 정책 봇 3종(신규: 반응 250ms·오조작 15%, 중급: 150ms·5%, 숙련: 90ms·1%)을 시드 1,000판씩 돌려 Stage별 클리어율, Hull 손실, 카드 선택 분포를 CSV로 출력한다.
- 카드 픽률·승률 기여도는 평균 대비 ±35% 이내. +25%p를 넘는 카드는 너프 후보로 자동 표시한다.
- 모든 패턴의 Solvability 테스트와 봇 기반 클리어율 회귀 테스트를 CI에 포함한다.

### 6.6 적응형 지원 (투명하게 표시)

- **첫 3판 보호**: 쉴드 재충전 −30%, 첫 사망 시 1회 Second Wind(Hull 2로 즉시 부활, 기록에 표기).
- **연속 사망 보정**: 같은 Stage에서 2연속 사망하면 다음 판 시작에 Repair 1 + 리롤 +1을 주고 응원 버프 아이콘으로 명시한다. 랭킹(Daily)에는 적용하지 않는다.

## PART 8. 멀티플레이어 기술 명세

### 8.1 플레이 형태

- **Online Co-op**: 방 코드·링크로 2인 접속. **Local Co-op**: 한 기기에서 2인(네트워크 코드 우회). **Solo**: 동행 드론(주 원소 보완, 3.7 참조).
- v1.1 후보: 빠른 매칭(시그널링 서버 인메모리 대기열). v1.0 범위에는 넣지 않는다.

### 8.2 접속 흐름

1. 호스트가 방 만들기 → 시그널링 서버가 5자리 코드 발급(알파벳 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, 혼동 문자 제외). 링크 `https://<domain>/#/join/ABCDE`, QR, Web Share API 제공.
2. 게스트가 코드 입력 또는 링크 진입 → 서버가 SDP·ICE를 중계 → WebRTC DataChannel 연결(STUN 공용 + TURN은 Cloudflare TURN 또는 coturn).
3. ICE가 8초 안에 실패하면 서버 WebSocket **릴레이 폴백**(같은 프로토콜, 지연 경고 표시).
4. 로비: 기체·준비 완료 표시, 난이도·모드는 호스트가 결정해 게스트에 표시 → 호스트 시작 → 3초 카운트다운.

### 8.3 시그널링·릴레이 서버 (DB 없음)

- `server/`: **Cloudflare Workers + Durable Object**(방당 1개, 인메모리 상태만 사용, 영구 저장소 미사용). 대안으로 Node.js `ws` 구현(Fly.io·Render)도 같은 인터페이스로 제공한다.
- 책임: 방 생성·참가(방당 최대 2명), SDP·ICE·릴레이 프레임 중계, 방 TTL(비어 있으면 2분, 최대 4시간). 게임 로직은 서버가 알지 못한다.
- 제한: IP당 방 생성 5/분, 참가 시도 20/분, 시그널 메시지 ≤ 4KB, 릴레이 프레임 ≤ 1KB, 연결당 120메시지/초. 참가 실패가 5회/분이면 쿨다운.
- 보안: Origin 화이트리스트, 방 목록 열거 불가, 개인정보·메시지 내용 미저장, 모든 입력 길이·타입 검증.
- 비용: P2P 위주라 서버 트래픽은 시그널링 수준이다.

### 8.4 권한 모델 — 호스트 권위(확정)

근거: 카드·드롭 RNG와 보스 패턴 일관성 확보, 락스텝의 부동소수점 비결정성 위험 회피, 2인 PvE라 치팅 위험이 낮음.

- **호스트**: 60Hz 시뮬레이션 전체(적·탄·드롭·보스·드래프트 RNG)를 소유하고 게스트 입력으로 게스트 기체를 시뮬한다.
- **게스트**: 입력 전송 + 자기 기체 로컬 예측 + 스냅샷 보간 렌더.
- 시간 동기: 호스트 tick 기준. 접속 직후 ping-pong 8회의 중앙값으로 클록 오프셋을 추정한다.

### 8.5 틱과 패킷

- 시뮬 60Hz, 스냅샷 20Hz(불안정 시 12Hz), 게스트 입력 30Hz + 직전 입력 3개 중복 전송.
- DataChannel 2개: `fast`(unordered, maxRetransmits 0) = 입력·스냅샷 / `ctrl`(ordered, reliable) = 이벤트·카드·로비·결과.
- 입력: `seq u16, tick u32, axis i8(-127~127), buttons u8(dash, burst, ping)`.
- 스냅샷: 바이너리(DataView), 항목별 델타. 플레이어 2명(위치 u16, hull, shield, flags), 적(id u16, type u8, x·y u16 양자화, hp% u8), 보스 상태, Tether·Resonance, 드롭. 목표 평균 ≤ 6KB/s, 피크 ≤ 12KB/s.
- **탄은 스냅샷에 싣지 않는다.** 호스트가 `spawnPattern` 이벤트(패턴 id, 시드, 발사체 id, tick)를 보내면 양쪽이 결정론적으로 탄을 시뮬한다. 탄 이동식은 고정소수점 선형·룩업 테이블(`Math.sin` 직접 사용 금지)로 브라우저 간 결과를 일치시킨다.
- 피격·충돌 판정은 호스트가 하고 `hit` 이벤트로 통지한다. 호스트가 1초마다 `bulletCount + hash` 체크섬을 보내고 불일치하면 `resync`로 해당 탄을 스냅샷 방식으로 재동기화한다.
- 아군 탄: 게스트는 자기 탄을 즉시 로컬 표시(코스메틱)하고, 데미지는 호스트가 게스트 입력 이력(최대 150ms)으로 위치를 보정해 판정한다.

```ts
type Ctrl =
  | { t: 'hello'; proto: number; build: string; token: string; chassis: ChassisId }
  | { t: 'lobby'; heat: number; mode: Mode; seed?: number; ready: boolean }
  | { t: 'start'; seed: number; balanceVersion: number; startTick: number }
  | { t: 'spawnPattern'; id: number; pattern: PatternId; seed: number; origin: EntityId; tick: number }
  | { t: 'hit'; tick: number; target: PlayerId; dmg: number; src: BulletClassId }
  | { t: 'draft'; player: PlayerId; offers: CardId[]; deadlineTick: number }
  | { t: 'pick'; player: PlayerId; card: CardId }
  | { t: 'ping'; kind: 0 | 1 | 2 | 3; x: number }
  | { t: 'checksum'; tick: number; bulletCount: number; hash: number }
  | { t: 'runResult'; stage: number; score: number; stats: RunStats };
```

### 8.6 지연 보정

- 보간 지연 100ms(스냅샷 2개 버퍼). RTT > 200ms면 150ms로 늘리고, 손실 > 10%면 스냅샷 12Hz로 낮춘다.
- 게스트 자기 기체는 클라이언트 예측(좌우 1축이라 단순). 호스트 위치와 오차 > 6px면 80ms에 걸쳐 보정, > 40px면 즉시 스냅.
- 대시 등 스킬은 게스트가 즉시 실행하고 호스트가 확정한다. 거부 시 롤백한다(드문 경우).
- 카드 선택은 reliable로 보내고 호스트가 확정 응답한다.

### 8.7 연결 품질과 끊김

- 하트비트 1초. 3초 무응답 → 파트너 연결 불안정 오버레이, 10초 → 호스트 시뮬 일시정지(최대 30초). 같은 방 코드 + `playerToken`(sessionStorage UUID)으로 재접속하면 전체 스냅샷으로 복구한다.
- 30초 초과: 게스트 이탈 시 호스트는 동행 드론과 솔로로 이어간다. 호스트 이탈 시 게스트는 마지막 스냅샷 기준 런 요약을 받고 보상의 70%를 정산한다(호스트 마이그레이션은 v1 범위 밖).
- 탭 비활성(`visibilitychange`) 5초 초과 시 일시정지·재연결 흐름을 탄다. iOS Safari 백그라운드 연결 끊김을 반드시 테스트한다.
- 연결 상태 아이콘(초록/노랑/빨강)과 RTT를 표시한다.

### 8.8 협동 UX

- **핑 4종**(여기 / 위험 / 모여 / 고마워): 3초 표시, 쿨 1.5초. 텍스트 채팅은 없다.
- 파트너 HUD: Hull, 쉴드, Resonance, 스킬 쿨. 링크 거리 가이드: 범위 이내면 실이 밝아지고 밖이면 점선 + 색 변화.
- 결과 화면: MVP 지표 4개 + 공명 지표(링크 시간 %).
- **로컬 코옵**: 한 시뮬 인스턴스에 입력 2개. 터치는 화면 좌/우 절반이 각 플레이어의 드래그 영역, 스킬 버튼은 각자 하단 코너.

### 8.9 보상 정산과 신뢰

- 각자 로컬 프로필에 보상을 저장한다. 게스트 보상은 호스트가 보낸 `runResult`로 계산하되 `stardust ≤ f(stage, duration, heat)` 상한으로 클램프한다.
- 글로벌 랭킹이 없으므로 치트 영향은 로컬·비교 불가 보상에 한정된다.

### 8.10 개발·테스트 도구 (필수)

- `?netsim=latency,jitter,loss`(기본 120,30,5%)로 인위적 네트워크 열화를 재현한다.
- 2봇 e2e(Playwright 컨텍스트 2개 + 로컬 시그널링 서버): 방 생성 → 참가 → Stage 1 클리어 → 연결 끊김·재접속 시나리오.
- `protoVersion` 불일치 시 접속을 거부하고 업데이트 안내(서비스 워커 업데이트 트리거).

## PART 9. 저장과 데이터 (서버 DB 없음)

### 9.1 원칙

모든 영속 데이터는 클라이언트에 저장하고, **소실될 수 있다는 전제**로 설계한다(백업 코드, 설치 유도, 복구 화면).

### 9.2 저장소 계층

- **IndexedDB** `lumen-tether` v1, object store `kv`(key → JSON). 키: `profile`, `settings`, `runSave`, `stats`, `daily`, `codex`, `missions`. `idb` 라이브러리 사용.
- **localStorage 미러**: 핵심 프로필을 압축·base64로 `lt.mirror`에 복제(IndexedDB 삭제·접근 실패 시 복구용). 설정은 `lt.settings`에도 저장.
- 메모리 캐시 + write-behind(디바운스 500ms). 런 종료·구매·설정 변경·`pagehide`·`visibilitychange: hidden`에서는 즉시 flush.
- 멀티 탭: `navigator.locks` + `BroadcastChannel`로 쓰기 충돌을 막고, 두 번째 탭은 읽기 전용 경고를 띄운다.

### 9.3 스키마

```ts
interface Profile {
  schema: number;                 // 현재 1
  balanceVersion: number;
  createdAt: number;
  lastSeenAt: number;             // 단조 증가 검증용

  stardust: number;
  lumenCores: number;

  equipped: { chassis: string; paint: string; trail: string; tether: string; title: string };
  mastery: Record<string, number>;
  heat: { unlocked: number; clears: Record<string, number> };

  achievements: Record<string, number>;
}

interface RunSave {
  schema: number; mode: string; heat: number; seed: number; stage: number;

```

### 9.4 무결성과 마이그레이션

- 모든 저장 값에 `schema`와 `crc32`(JSON 문자열 기준)를 함께 저장한다. 읽기 검증에 실패하면 미러 → 백업 순으로 복구하고, 모두 실패하면 사용자에게 알린 뒤 새 프로필로 시작한다. 손상본은 삭제하지 않고 `*.corrupt` 키로 보관한다.
- `migrations: Array<(old) => new>`를 순차 적용하고 골든 픽스처 단위 테스트를 둔다.
- `balanceVersion`이 바뀌어 호환되지 않으면 `runSave`를 폐기하고 안내한다.

### 9.5 백업과 기기 이전

- **Export**: `LT1.` + base64url(deflate(JSON)) + `.` + crc32 형식의 텍스트 코드(복사) 또는 `.lumen` 파일. **Import**: 검증 → 미리보기(Stardust, 해금 수) → 덮어쓰기 / 병합(큰 값 우선, 해금은 합집합) 선택.
- 설정 화면과 주 1회 토스트로 백업을 권유한다.

### 9.6 브라우저 제약 대응 (중요)

- iOS Safari는 홈 화면에 설치하지 않은 사이트의 스크립트 저장소를 약 7일 미사용 시 삭제할 수 있다. 3번째 세션 종료 시점에 홈 화면 추가를 안내하고(설치 시 면제), 앱 시작 시 `navigator.storage.persist()`를 요청한다.
- 프로필이 없는데 과거 방문 흔적(별도 플래그)이 있으면 복구 코드로 복원 화면을 띄운다.
- 사생활 보호 모드·저장소 차단 시 메모리 모드로 폴백하고 진행이 저장되지 않음을 배너로 알린다.
- 전체 저장 용량 목표: 200KB 미만.

### 9.7 런 저장과 재개

- 솔로: Stage 시작과 Gateway 종료 시 `runSave` 체크포인트. 재시작 시 이어하기(체크포인트부터).
- 코옵 런은 재개할 수 없고 결과만 정산한다.
- 사망·클리어 시 `runSave`를 삭제한다. 이어하기를 이용한 보상 파밍을 막기 위해 `earned`로 런 누적 보상을 추적하고 체크포인트 이후 증가분만 가산한다.

### 9.8 프라이버시·법무

- 개인정보 수집 없음(계정·이메일 없음). 설정 > 정보에 로컬 저장 고지를 둔다.
- 분석은 `Analytics` 어댑터 인터페이스만 제공하며 기본 no-op, 켜기 전 동의가 필요하다. 어린 이용자를 고려해 기본값은 광고·추적 없음이다.

## PART 10. 아키텍처 · 기술 스택 · 성능 예산

### 10.1 기술 스택 (확정)

- **언어·빌드**: TypeScript(strict) + Vite. ESLint + Prettier. CI는 GitHub Actions.
- **렌더링**: PixiJS v8(WebGL). WebGL 미지원 기기는 안내 화면을 보여 준다.
- **UI**: Preact + signals. 게임 오브젝트는 Pixi, HUD·메뉴·카드는 DOM 오버레이(접근성·텍스트 렌더 품질).
- **PWA**: vite-plugin-pwa(Workbox), 오프라인 프리캐시, 업데이트 토스트.
- **저장·압축**: `idb`, `fflate`.
- **네트워크**: 네이티브 WebRTC 위에 `Transport` 인터페이스(WebRTC / WebSocket 릴레이 / Local)를 두고 구현을 교체 가능하게 만든다.
- **오디오**: 자체 WebAudio 합성 엔진(파라메트릭 SFX + 스텝 시퀀서).
- **테스트**: Vitest(시뮬·밸런스·마이그레이션), Playwright(e2e, 2인 접속 포함).
- **i18n**: 경량 `t(key)` + `ko.json` / `en.json`. 폰트는 OFL 라이선스 폰트를 서브셋한 woff2(합계 ≤ 120KB).

### 10.2 아키텍처 원칙

- **Sim / Render / UI 분리**: `core/sim`은 순수 TS(DOM·Pixi 의존 0, 결정적, 헤드리스 실행 가능). 렌더와 UI는 Sim 상태를 읽기만 한다.
- Sim: 고정 60Hz, ECS-lite(SoA 타입드 배열), **오브젝트 풀링(핫패스 할당 0)**, 공간 해시 그리드(셀 64px) + 원형 충돌, 시스템별 시드 PRNG 스트림(`sfc32`: spawn / loot / draft / fx).
- 입력은 `InputFrame`으로 추상화(키보드·터치·패드·네트워크·봇 공통).
- 상태 머신: Boot → Menu → Lobby → Run(Stage → Act → Lull/Boss → Gateway) → Result.
- 데이터 주도: `data/`는 빌드 시 스키마 검증(zod 또는 동등한 검증).
- 플랫폼 어댑터: `PlatformAdapter { save, share, ads?, lifecycle, haptics }`를 웹 / 포털 / Capacitor별로 구현한다.
- **결정성 규칙**: Sim 내부에서 `Math.random`, `Date.now`, `Math.sin/cos` 직접 호출 금지(PRNG·룩업 테이블 사용). ESLint 커스텀 룰로 강제한다.

## PART 11. UI · UX · 접근성 · 타격감

### 11.1 화면 흐름

Boot → Title(Play / Co-op / Hangar / Codex / Settings) → 모드 선택 → 기체·Heat 선택 → (코옵 로비) → Run → Gateway(경로·상점·이벤트) → Result(점수, MVP, Stardust 정산, 공유 카드, 다시하기) → Hangar·Codex.

- 주요 버튼은 엄지가 닿는 하단 60%에 둔다. 터치 타깃 ≥ 48px. 모든 화면은 한 손으로 사용 가능해야 한다.
- 일시정지: 계속 / 설정 / 포기(확인) / 메인. 코옵에서는 호스트만 일시정지하고 게스트는 요청을 보낸다. 코옵 일시정지는 최대 60초 후 자동 해제.

### 11.2 HUD (세로 화면)

- 상단 중앙: 점수·콤보. 최상단 얇은 바: Stage·Act 진행. 보스전: 보스 HP 바 + 페이즈 틱.
- 좌상단: 파트너 미니 패널(Hull, 쉴드, Resonance, 스킬 쿨).
- 하단 모서리: 내 Hull 칸 / 쉴드 / 스킬 버튼(손가락이 기체를 가리지 않게 배치). 하단 가장자리: 얇은 XP 바.
- 드래프트: 하단 60%에 큰 카드 3장(탭 선택), 파트너 선택 완료 표시. 카드에는 아이콘·한 줄 효과·현재 Lv→다음 Lv 수치를 표시한다.
- 안전 영역(`safe-area-inset`)과 시스템 제스처 영역을 피한다.

### 11.3 FTUE — 첫 90초 설계

1. 0\~10초: 텍스트 없이 드래그 아이콘 + 첫 적.
2. 10\~25초: 첫 젬 → 첫 레벨업(≤ 25초). 첫 카드 3장에는 직관적인 카드(증폭 탄두·이중 사격 등)를 반드시 포함한다.
3. 25\~45초: 느린 탄으로 첫 그레이즈를 유도하고 노란 링 피드백으로 보상한다.
4. 60초 부근: 램퍼의 텔레그래프 → 대시 안내(1회).
5. Nova 게이지 100% 시 1회 안내. 코옵 첫 플레이 시 Tether 거리 가이드 → 첫 Resonance 100에서 Duet Burst 안내.

- 안내는 맥락 트리거로 짧게 보여 주고 일시정지 팝업은 최소화한다. 건너뛰기 상시 제공, 설정에서 다시 볼 수 있다.

### 11.4 타격감(Juice) 스펙

- 히트스톱: 엘리트 처치 40ms, 보스 페이즈 브레이크 90ms, 플레이어 피격 60ms.
- 카메라 셰이크: Small 2px/80ms, Mid 5px/140ms, Big 10px/260ms. 설정으로 0\~100% 조절.
- 처치: 적 크기에 비례한 파편 + 링, 젬 흡수 트레일. 콤보 UI 펀치(스케일 1.0→1.25→1.0, 120ms)와 콤보에 따른 음계 상승.
- 보스 처치: 0.3× 슬로 1.2초 + 화이트 플래시(플래시 감소 설정 시 생략).
- 레벨업: 시간 정지 없이 링 파동 + 짧은 아르페지오 + 카드 대기 아이콘.
- 데미지 숫자: 풀링, Mid 티어 이상에서만 표시. 크리티컬은 확대·색상 변경.

### 11.5 접근성 (필수)

- 플래시·깜빡임 감소 토글, 전체 화면 플래시는 초당 3회 이하로 제한.
- 화면 흔들림 슬라이더, 탄 가시성 모드(High Contrast: 적 탄 흰색 2px 외곽 + 아군 탄 투명도 하향), 색약 모드(모양 구분 강화 + 팔레트 변경), 텍스트 크기 100 / 125 / 150%.
- 입력: 키 리바인딩, 터치 민감도, 좌·우손 레이아웃, **원버튼 모드**(탭 = 대시, 길게 = Nova).
- 스크린리더: DOM 메뉴에 aria 라벨. 핵심 이벤트는 시각·소리·진동 중 2채널 이상으로 전달한다. 모든 경고는 소리 없이도 인지 가능한 시각 텔레그래프를 가진다.
- `prefers-reduced-motion`을 자동 반영한다.

### 11.6 설정 화면 항목

오디오 3슬라이더, 진동, 그래픽 품질(자동/Low/Mid/High), 프레임(60/30), 화면 흔들림, 플래시 감소, 탄 가시성, 색약 모드, 텍스트 크기, 조작(민감도, 버튼 위치·크기·반전, 키 설정), 언어, Classic Pause(레벨업), 데이터(내보내기·가져오기·초기화), 정보(버전, 라이선스, 개인정보).

### 11.7 카피와 톤

짧고 시적인 한 줄. 예: Stage 1 카피 `불씨를 놓치지 마`, 보스 입장 연출은 이름만 크게. 모든 문자열은 `i18n/*.json` 키로 관리하고 하드코딩하지 않는다.

### 12.6 업데이트 정책
