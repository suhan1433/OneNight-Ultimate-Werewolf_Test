# 천원(天元) — 오목 택틱스 최종 기획안 v1.0

Nov 23, 2026 · @조

## 2. 컨셉: 돌에 영웅이 깃든 신전에서 벌이는 한 판의 전쟁 영화

플레이어는 달이 기운 밤, 천원(판의 중심) 신전에서 마주 앉은 두 대국자다. 돌을 놓으면 그 돌에 깃든 영웅, 석혼(石魂)이 깨어나 판 위에서 싸운다. 한 판은 서막·격돌·결전의 3막으로 흘러가고, 마지막 5목이 완성되는 순간이 클라이맥스 컷신이 된다.

**톤**: 고요 → 한 수 → 파문. 평소 화면은 정적이고 어둡게 두고, 연출은 짧고 강하게 터뜨려 대비로 긴장을 만든다.

**핵심 판타지 3가지**

1. 한 수가 한 장면이다. 착수, 스킬, 합성, 증강 선택마다 고유한 컷이 있다.
2. 내 덱이 내 이야기다. 특성과 증강 조합으로 매 판 다른 영웅단이 만들어진다.
3. 읽고, 속이고, 뒤집는다. 상대의 특성과 마나를 보고 카운터 수를 준비한다.

**설계 기둥 4가지**

- 오목이 주인공이다. 턴당 스킬은 1회, 플레인 스톤이 항상 안전망이 된다.
- 예고와 반응. 판을 바꾸는 효과는 반드시 상대에게 반응할 한 턴을 준다.
- 역전의 서사. 추격 보너스, 제단 우선 선택, 카운터 스킬이 뒤진 쪽에 길을 열어 준다.
- 연출이 곧 정보다. 이펙트의 모양과 색이 효과의 종류와 위협 정도를 말해 준다.

## 3. 한 판의 3막 구조: 막마다 증강과 제단이 사건을 만든다

한 판은 서막(R1\~4)·격돌(R5\~10)·결전(R11\~)의 3막이다. 막이 바뀔 때는 타이틀 카드와 음악 전조로 분위기를 바꾼다.

제단(R4·R8·R12)과 증강(R3·R7·R11)이 막마다 한 쌍씩 사건을 만들고, 긴장도는 막이 넘어갈수록 높아진다. 마지막 한 수 컷신이 3막의 클라이맥스다.

## 4. 확정 룰: 예고 규칙 하나로 승부처를 지킨다

13×13 보드에서 라운드마다 준비 → 선공 1턴 → 후공 1턴을 진행하고, 승리는 착수가 만든 5목으로만 결정된다. 스킬이 아무리 강해도 상대에게 반응할 한 턴을 반드시 남긴다.

| 항목 | 확정 내용 |
| --- | --- |
| 인원/보드 | 1:1, 13×13. 선공은 금화 동전 던지기 연출로 결정 |
| 승리 조건 | 가로·세로·대각선 5목 이상 (장목 허용, 금수 없음). 토큰은 연결 판정에서 제외 (대지의 정령왕만 예외) |
| 라운드 | 준비 20초(동시) → 선공 턴 30초 → 후공 턴 30초 → 자동 정산 |
| 한 턴 | 착수 1개(필수) + 스킬 1회(선택, 마나 소모) |
| 플레인 스톤 | 무료·무제한·스킬 없음. 벤치가 비어도 항상 둘 수 있다 |
| 마나 | 최대 = 레벨 + 2, 턴 종료 시 +2. 선공 시작 0 / 후공 시작 2 |
| 시간 초과 | 자동 대리 착수(가장 위협적인 칸을 막는 휴리스틱). 누적 3회면 기권 처리 |
| 정보 공개 | 보드·특성·레벨·골드·마나·사용한 증강은 공개, 상점·벤치·증강 후보는 비공개 |

**예고 규칙** (v0.1의 승부처 보호·5목 유예·승부처 세금을 통합)

1. 스킬(제거·봉인·밀기·교환·토큰 연결·추가 착수)이 새로 만든 이기는 칸은 그 턴에 쓸 수 없다. 상대 턴이 지난 뒤에야 쓸 수 있다.
2. 스킬이 직접 5목을 만들어도 즉시 승리가 아니다. 상대 턴을 지나 자기 턴 시작 시점에 유지되면 승리한다.
3. 이기는 칸(상대의 4목 완성 자리)은 토큰·착수 금지·밀기로 직접 막을 수 없다. 직접 착수하거나 라인의 돌을 봉인·제거해야 한다.
4. 방금 둔 돌은 다음 상대 턴 동안 스킬 대상이 될 수 없다(착수 보호).
5. 추가 착수로 둔 돌은 5목을 완성할 수 없다.

## 5. 경제와 성장: 12\~16라운드 판에 맞춰 곡선을 다시 맞췄다

레벨은 R3·R6·R9·R12·R15에 Lv4·5·6·7·8이 되도록 설계했다. Lv8까지 모든 XP를 사서 올려도 15라운드 총수입 80골드의 40%(32골드)라서, 레벨과 유닛 구매 사이에 진짜 선택이 남는다.

- 시작 골드 5, 라운드 수입 5 + 이자(10골드당 +1, 최대 +5)
- 상점 5칸, 리롤 2골드, 경험치 구매 4골드 = 4XP, 라운드마다 자동 +2XP
- 최대 마나 = 레벨 + 2, 벤치 9칸, 판매가는 구매 총액과 같다
- **상단 안전장치**: 상단 계열 효과로 얻는 골드는 라운드당 합계 +4까지 (이자 제외)
- **추격 보너스**: 라운드 종료 시 판세 점수가 낮은 쪽에 +1골드, 격차 4점 이상이면 +2골드. 판세 점수는 열린 3 = 2점, 막힌 4 = 2점
- **리롤 보호**: 리롤 누적 12회마다 현재 레벨의 최고 코스트 돌 1장을 보장

## 6. 운명의 제단과 증강: 라운드마다 사건을 만든다

R4·R8·R12에는 제단이 열려 공용 석혼 4장을 나눠 갖고, R3·R7·R11에는 증강을 하나 고른다. 1:1에는 롤토체스의 캐러셀이 없으므로, 제단이 그 자리를 대신해 두 플레이어가 직접 부딪히는 순간을 만든다.

**운명의 제단 (공용 드래프트)**

- 시점: R4, R8, R12의 준비 페이즈 시작 직후. 12라운드 전에 끝난 판에서는 열리지 않는다
- 석혼 4장이 제단에 뜬다. R4는 1\~2코, R8은 2\~3코, R12는 3\~4코 중에서 뽑는다
- 선택 순서: 판세 점수가 낮은 쪽 1장 → 높은 쪽 2장 → 낮은 쪽 1장. 동점이면 후공이 먼저
- 제단에서 나온 돌은 공용 풀에서 빠진다. 선택 제한 시간은 15초

**증강**

- R3 실버, R7 골드, R11 프리즘의 3지선다 + 리롤 1회. 후공은 첫 증강 선택지가 4개
- 선택지 3개는 서로 다른 분류가 2종 이상 섞인다. 판세 점수가 낮은 쪽은 선택지 1개가 상위 티어로 교체된다
- 고른 증강은 상대에게 공개된다. 가치 기준은 실버 8골드 / 골드 16골드 / 프리즘 28골드 상당을 초기 목표로 두고 시뮬레이션 승률로 보정한다

## 7. 캐릭터 24종: 특성마다 5\~7명, 코스트 7·6·5·4·2

캐릭터 돌은 코스트 1\~5, 특성 2개, 스킬 1개를 가진다. 스킬은 배치 시(착수 즉시 1회), 패시브(보드에 있는 동안), 액티브(마나 소모, 턴당 1회, 기본 쿨다운 2턴) 중 하나다. ★2는 수치(턴 수·골드·마나)가 1.5배(올림), ★3는 대상 +1개 또는 범위 확장이다.

**키워드**

- 방패: 제거·이동·봉인·교환 중 1회를 무효로 하고 사라진다
- 봉인: N턴 동안 그 돌을 연결 판정에서 제외한다 (돌은 남는다)
- 토큰: 빈 칸을 차지하는 소환물. 연결 판정 제외, 방패 불가, 모든 스킬로 제거할 수 있다

**아키타입 가설 (플레이테스트로 검증)**

- 속공형(자객·마법사): 스킬로 선제 압박. 확장형을 초반에 누른다
- 철벽형(수호자·군단): 방패와 연결 유지. 속공형의 스킬을 무력화한다
- 확장형(정령사·상단): 토큰과 경제로 후반 우위. 철벽형을 자원전으로 앞선다
- 교란형(환영술사·시간술사): 상성이 고정되지 않은 카운터 선택지로, 읽기 실력이 승패를 가른다

**위험 조합과 안전장치 (시뮬레이션 우선 검증)**

| 조합 | 위험 | 안전장치 |

## 9. 밸런스 설계: 예산, 지표, 튜닝 순서를 미리 정해 둔다

24종 스킬은 모두 코스트별 가치 예산과 마나 상한 안에서 설계했고, 스크립트로 전부 통과를 확인했다. 아래 수치는 출시 전 시뮬레이션과 베타에서 보정할 초기값이다.

**오목 특유의 문제와 해법**

| 문제 | 위험 | 해법 |
| --- | --- | --- |
| 선공 우위 | 선공이 압도 | 후공 보정 (§4) |
| 제거·이동 스킬 남용 | 방어 불능, 불쾌감 | 방패, 착수 보호, 쿨다운, 예고 규칙 |
| 필승기 | 오목의 긴장감 파괴 | 예고 규칙 1\~5, 5코 스킬은 게임당 횟수 제한 |
| 스노우볼 | 앞서면 끝 | 추격 보너스, 제단 선택 우선권, 심판자·반격 태세, 마나 상한 |
| 상점 RNG | 운 승부 | 공유 풀, 리롤 보호, 제단, 증강 3지선다 |
| 경제 과잉 | 올인 경제 | 이자 상한 +5, 상단 +4 상한, XP 곡선 |

**스킬 파워 예산**: 효과 가치의 합이 코스트 예산 이내(±10%)여야 한다. 패시브는 상시 발동 프리미엄으로 ×1.2, ★2는 ×1.5, ★3는 ×2.2로 계산한다. 마나와 쿨다운은 가치에 넣지 않고 코스트별 상한으로 따로 관리한다.

| 효과 | 가치 | 효과 | 가치 |
| --- | --- | --- | --- |
| 방패 1회 / 골드 +1 / 마나 +1 | 1 | 적 돌 1칸 밀기 / 토큰(3턴) | 1.5 |
| 적 돌 봉인(2턴) | 2 | 상대 마나 -2 | 2.5 |
| 위치 교환 / 적 돌 제거 | 3 | 라인 전체 봉인(2턴) | 4.5 |
| 시간 정지(상대 스킬 차단 1턴) | 6 | 추가 착수 | 8 |

| 코스트 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 가치 예산 | 2 | 3.5 | 5 | 7 | 9 |
| 마나 상한 | 2 | 4 | 5 | 5 | 7 |

**목표 지표**

| 지표 | 목표 |
| --- | --- |
| 선공/후공 승률 | 50 ± 2% |
| 캐릭터별 승률 (보드에 있을 때, 1,000판 이상) | 45\~55% |
| 특성별 승률 | 47\~53%, 픽률 상위 특성은 54% 상한 |
| 아키타입 4종 픽률 | 각 15\~35% |
| 증강 단일 픽률 | 35% 이하 |
| 스킬 사용 턴 비율 | 40\~60% (오목 주도권 유지) |
| 평균 길이 | 12\~16라운드, 10\~12분 |
| 8라운드 이전 종료 | 10% 이하 |
| 추격 보너스를 받은 쪽의 승률 | 30% 이상 |

**튜닝 순서**: 한 패치에 한 요소만 바꾼다. 수치(마나·쿨다운·턴 수) → 코스트 → 풀 크기 → 효과 설계 변경 순으로 손대고, 효과 변경은 마지막 수단으로 둔다.

**검증 3단계**

1. 종이 프로토타입(카드와 바둑돌, 2인 20판)으로 룰 구조와 예고 규칙을 먼저 검증한다
2. 헤드리스 룰 엔진과 봇(휴리스틱 + MCTS, 3단계 실력)으로 수만 판 자가대국을 돌려 승률 행렬을 만든다
3. 클로즈드 베타에서 위 지표와 같은 이벤트를 수집해 실제 값과 비교한다

## 10. 영화적 연출 설계: 긴장도가 카메라와 음악을 움직인다

연출의 규칙은 하나다. 판 위의 긴장이 높아질수록 화면은 조여들고 소리는 깊어진다. 연출은 정보를 대신하지 않고 정보를 강조하며, 입력을 막지 않는다.

**아트 디렉션: 월광 신전 × 수묵**

| 요소 | 설계 |
| --- | --- |
| 팔레트 | 심야 남색 #0B1020, 먹빛 #1A1F2E, 금박 #E8C170 (공통 강조), 청옥 #5CE1E6 (내 쪽), 주홍 #FF6B5A (상대 쪽) |
| 돌 | 선공 흑석(먹빛 + 금 테두리), 후공 백석(옥빛). 캐릭터 돌은 고유 문양을 음각하고 코스트 링으로 등급을 표시: 1코 회색, 2코 청, 3코 보라, 4코 금, 5코 금 + 빛기둥 |
| 카메라 | 2.5D 55° 기울기, 미세 패럴랙스, 비네팅과 피사계 심도, 컷신에서는 2.39:1 레터박스 |
| 타이포 | 제목은 명조 + 붓글씨 계열, 본문과 수치는 산세리프. 한글·한자 모두 지원하는 웹폰트 |
| 색약 대응 | 내 돌은 원형 링, 상대 돌은 마름모 링을 함께 쓴다. 색만으로 구분하지 않는다 |

**사운드**: 음악은 패드, 현악, 타악, 합창의 4개 스템을 긴장도에 따라 크로스페이드하고, 막이 바뀔 때 전조한다. 가야금·대금 같은 국악기 음색을 오케스트라에 섞어 고유한 정체성을 만든다. 착수음은 돌과 목판이 부딪히는 소리, 스킬마다 시그니처 효과음을 두고, 시간 정지 때는 저역 필터와 심장박동을 쓴다.

**긴장도(Tension) 시스템**: 룰 엔진이 매 턴 계산해 연출 레이어에 넘기는 0\~1 값이다. 초기 가중치는 플레이테스트로 보정한다.

```latex
T = min(1, 0.15 n_3 + 0.4 F + 0.2 L + 0.1 M)
```

n3 = 양쪽의 열린 3 개수, F = 4목 존재 여부(0/1), L = 남은 시간 10초 이하 여부(0/1), M = 마나 가득 여부(0/1).

| 긴장도 | 상태 | 연출 |
| --- | --- | --- |
| 0 \~ 0.3 | 고요 | 패드만 재생, 카메라 정지, 안개가 천천히 흐른다 |
| 0.3 \~ 0.6 | 긴장 | 타악 합류, 카메라 +2% 줌, 위협 라인이 맥동 |
| 0.6 \~ 1 | 임계 | 합창 합류, 카메라 +6% 줌, 비네팅 강화, 심장박동 |

**애니메이션 카탈로그** (길이와 이징은 구현 기준값)

| 이벤트 | 연출 | 길이·이징 |
| --- | --- | --- |
| 착수 | 돌이 위에서 낙하, 충돌 시 파문과 먼지, 보드 2px 진동 | 220ms · ease-in → ease-out |
| 석혼 각성 | 캐릭터 돌에서 영웅 실루엣 광륜이 팝, 문양 점등 | 320ms · ease-out-back |
| 특성 활성 | 같은 특성의 돌을 잇는 금빛 선이 그어지고 아이콘이 3회 맥동 | 400ms · stroke draw |
| 열린 3 | 해당 라인이 은은하게 맥동 | 1.2s 루프 · opacity 0.3↔0.6 |
| 4목·승부처 | 0.6배속 슬로모션, 비네팅, 저역 필터, 심장박동 | 800ms |
| 스킬 시전 | 대상 칸에 파문 링 → 영웅 컷인이 측면에서 슬라이드 | 600ms + 400ms · 탭으로 스킵 |
| 봉인 | 사슬 글리프가 돌을 감는다 | 500ms |
| 제거 | 균열이 번지고 가루로 흩어진다 | 700ms |
| 밀기 | 충격파와 함께 슬라이드 | 250ms · ease-out-cubic |
| 교환 | 두 돌이 포털로 사라졌다 자리를 바꿔 나타난다 | 450ms |
| 토큰 | 안개 속에서 형상이 서서히 드러난다 | 400ms |
| 방패 | 육각 돔이 팝, 깨질 때 파편이 흩어진다 | 300ms · 파편 500ms |
| 시간 정지 | 채도 0, 파티클이 허공에 멈춘다 | 1.2s |
| 상점 | 카드 5장이 60ms 간격으로 딜링, 구매 시 곡선 비행으로 벤치 안착, 리롤은 카드 플립 | 카드당 300ms · rotateY |

| 라운드 전환 | 안개가 걷히고 달 위상 아이콘이 갱신, 라운드 카드 슬라이드 | 800ms |

**연출 원칙과 접근성**

- 입력 락은 최대 600ms다. 마지막 한 수 컷신만 예외이며 탭으로 스킵할 수 있다
- 연출 레벨 3단계(시네마틱·표준·최소)와 OS 모션 감소 설정 연동을 제공한다
- 60fps가 목표이고, 프레임이 떨어지면 파티클 수와 블룸을 자동으로 낮춘다
- 초당 3회 이상 깜빡이는 플래시는 쓰지 않는다
- 음악·효과음·음성 볼륨을 따로 조절하고, 착수와 임팩트에 햅틱을 연동한다

## 11. UI/UX: 한 손 세로 화면이 기본, 데스크톱은 같은 구조를 가로로 편다

모바일 세로를 기준으로 설계하고, 데스크톱은 같은 요소를 가로로 재배치한다. 화면은 한눈에 보이는 층, 한 번 탭하는 층, 길게 누르는 층의 3단으로 정보를 나눈다.

&#91;embedded content: 대국 화면 와이어프레임 · 모바일 세로와 데스크톱\]

1층은 항상 보이고, 2층은 탭 한 번, 상세(3층)는 길게 누르면 열린다.

**화면 목록**

| 화면 | 목적 | 핵심 요소 |
| --- | --- | --- |
| 타이틀 | 시네마틱 진입 | 신전 인트로 루프, 단일 버튼 \[대국 시작\] |
| 매칭 | 대기를 연출로 | 기반이 펼쳐지는 로딩, 상대 닉네임 공개, 선공 동전 던지기 |
| 대국 | 핵심 화면 | 보드, 상점, 벤치, 마나·골드·레벨, 특성 패널, 타이머 |
| 증강 선택 | R3·R7·R11 | 별자리 3지선다, 리롤 1회 |
| 운명의 제단 | R4·R8·R12 | 석혼 4장, 선택 순서 표시 |
| 결과 | 복기와 공유 | 하이라이트 3컷, 한 줄 복기, 다시 하기 |
| 튜토리얼 | 첫 판 | 가이드 AI와 R1\~R6 축소판 |
| 설정 | 연출·접근성 | 연출 레벨, 색약 모드, 볼륨, 햅틱 |

**3단 정보 위계**

- 1층(항상 표시): 보드, 양쪽 마나·골드·레벨, 타이머, 하이라이트된 위협 라인
- 2층(한 번 탭): 특성 패널, 상점과 벤치, 스킬 버튼
- 3층(길게 누르기): 캐릭터 상세, 상대 특성 상세, 스킬 범위 미리보기, 규칙 툴팁

**모바일 조작 규칙**

- 착수: 칸을 탭하면 반투명 미리보기가 뜨고 \[확정\]을 눌러 둔다. 오탭을 막기 위한 기본값이며 설정에서 한 번 탭 착수로 바꿀 수 있다
- 돌 선택: 벤치의 돌을 탭해 고르고 칸을 탭한다. 고르지 않으면 플레인 스톤을 둔다
- 스킬: 스킬 버튼 → 대상 칸에 범위 미리보기 → 확정. 마나가 부족하면 버튼이 흐려지고 필요 마나를 표시한다
- 상점: 준비 페이즈에 바텀 시트가 자동으로 올라오고 대국 페이즈에는 내려간다
- 핀치 줌은 없다. 13×13을 화면 폭에 맞추면 360px 기준 한 칸이 약 27px이라 미리보기·확정 방식으로 오탭을 막는다
- 주요 버튼은 엄지가 닿는 화면 하단 1/3에 둔다

**데스크톱**: 좌측에 특성·증강 패널, 중앙에 보드, 우측에 상대 정보와 로그, 하단에 상점·벤치를 둔다. 단축키는 1\~5 구매, D 리롤, F 경험치 구매, Space 확정, Esc 취소, Q·W 스킬이다.

**이펙트가 곧 정보 (표시 규칙)**

- 내 위협 라인은 청옥, 상대 위협 라인은 주홍으로 맥동하고, 이기는 칸에는 금빛 다이아 마커가 뜬다
- 봉인은 사슬 아이콘과 남은 턴 숫자, 방패는 육각 테두리, 토큰은 반투명 + 남은 턴 링으로 표시한다
- 스킬 범위 미리보기는 효과 종류별 색을 쓰되 모양도 달리해(원·십자·사각) 색에만 의존하지 않는다

## 12. 에이전트 빌드 가이드: 룰 엔진을 먼저 만들고, 연출은 이벤트로 얹는다

게임은 프레임워크에 의존하지 않는 TypeScript 룰 엔진 하나를 중심으로 만든다. 화면과 연출은 엔진이 내보내는 이벤트를 소비할 뿐이므로, 같은 엔진으로 서버 검증, 봇 자가대국, 리플레이 편집을 모두 할 수 있다.

**권장 스택 (웹·앱 공용)**

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 룰 엔진 | TypeScript 순수 함수 + 시드 기반 RNG | 결정적 시뮬레이션, 클라이언트·서버·봇 공용 |
| 보드·VFX 렌더링 | PixiJS(WebGL 2D) + GSAP 타임라인 | 파티클, 블룸·비네팅 필터, 2.5D 기울기 |
| UI | React + CSS 변수 + Framer Motion | 상점, 패널, 바텀 시트 |
| 오디오 | Howler.js 스템 크로스페이드 | 긴장도 연동 |
| 서버 | Node.js + WebSocket 룸 기반 권위 서버 | 비공개 상점 정보 보호, 부정 방지 |
| 배포 | PWA 우선, 이후 Capacitor로 iOS·Android | 단일 코드베이스 |

**핵심 원칙**

- 엔진 시그니처는 `(state, action, rng) → (state', events[])`다. 연출은 PLACE\_STONE, SKILL\_CAST, SEAL\_APPLIED, TRAIT\_ACTIVATED, FINAL\_MOVE 같은 이벤트를 받아 재생한다
- 서버 권위: 클라이언트는 의도(intent)만 보내고, 상점 롤과 풀 관리는 서버가 한다
- 데이터 주도: 캐릭터·특성·증강은 JSON 정의와 효과 프리미티브(addShield, seal, push, swap, spawnToken, grantGold, grantMana, extraPlace, freezeOpponent)의 조합으로 만든다. 밸런스 패치는 JSON 수정만으로 끝난다
- 연출 큐: 이벤트를 타임라인 큐에 넣고, 스킵·가속·최소 모드를 큐 단계에서 처리한다
- 라운드 상태 머신: ROUND\_START → (ALTAR 또는 AUGMENT) → PREP → TURN\_FIRST → TURN\_SECOND → SETTLE → ROUND\_END

**데이터 스키마 예시**

```json
{
  "id": "thunder_mage",
  "name": "번개 술사",
  "cost": 2,
  "traits": ["mage", "chrono"],
  "skill": {
    "type": "active",
    "mana": 3,
    "cooldown": 2,
    "target": { "kind": "enemy_stone" },
    "effects": [{ "op": "seal", "turns": 2 }],
    "vfx": "seal_chain",
    "value": 2.0
  },
  "star": { "2": { "scale": 1.5 }, "3": { "extraTargets": 1 } }
}
```

**마일스톤과 수용 기준**

| 단계 | 범위 | 수용 기준 |
| --- | --- | --- |
| M0 룰 엔진 | 13×13 오목, 승리 판정, 예고 규칙 5개 조항, CLI | 조항별 단위 테스트 통과, 무작위 1만 판 자가대국이 오류 없이 종료 |
| M1 경제·상점 | 골드·이자, 상점 확률, 공유 풀, 합성, 리롤 보호 | 상점 확률 시뮬레이션이 §5 표와 ±1%p 이내로 일치 |
| M2 데이터 | 캐릭터 24종, 특성 8종, 증강 12종 | 가치 예산·마나 상한·특성 도달 인원 검증 스크립트 통과 |
| M3 대국 화면 | 모바일 세로 UI, 확정 버튼 착수, 상점·벤치, 봇 대전 | 360px 폭에서 오탭 없이 착수, 입력 락 600ms 이하 |
| M4 시네마틱 | 이벤트 큐, 착수·스킬·합성·긴장도·마지막 한 수 | 중급 기기 60fps, 최소 모드에서 입력 지연 0, 스킵 동작 |
| M5 서버·매칭 | 권위 서버, 매치메이킹, 재접속 | 변조된 클라이언트 요청을 서버가 거부 |
| M6 베타 | 텔레메트리, 봇 승률 행렬, 패치 파이프 | §9 목표 지표 대시보드 가동 |

**텔레메트리 이벤트**: match\_start/end(선후공·길이), shop\_buy, reroll, level\_up, altar\_pick, augment\_pick(티어·후보), skill\_cast(캐릭터·효과), trait\_tier\_change, comeback\_bonus, win\_by(착수/스킬 유예), time\_out.

**에이전트에게 요청하는 순서 (단계별 프롬프트)**

1. M0: 이 문서 §4의 룰대로 TypeScript 룰 엔진과 단위 테스트를 만든다. UI는 만들지 않는다
2. M1\~M2: §5·6·7·8의 데이터를 JSON과 효과 프리미티브로 구현하고 §9 검증 스크립트를 포함한다
3. M3: 엔진 위에 §11의 모바일 세로 대국 화면과 봇 대전을 만든다
4. M4: §10의 애니메이션 카탈로그를 이벤트 큐로 구현하고 연출 레벨 3단계를 붙인다
5. M5\~M6: 서버와 텔레메트리를 붙이고 봇 자가대국으로 §9 지표를 측정한다

## 13. 로드맵과 열린 질문: 룰을 확정한 뒤에 연출을 입힌다

각 단계는 앞 단계의 목표 지표를 달성해야 다음으로 넘어간다.

1. **MVP (M0\~M4)**: 1:1 봇 대전, 캐릭터 24종, 연출 레벨 3단계, 첫 판 튜토리얼
2. **온라인 베타 (M5\~M6)**: 매칭, 텔레메트리, 봇 승률 행렬 기반 밸런스 패치
3. **시즌제**: 시즌마다 특성 일부와 증강 풀을 교체하고(롤토체스의 시즌처럼), 연출 스킨을 추가한다
4. **8인 토너먼트 모드**: 9×9 미니 보드에서 4쌍이 동시에 대국하고, 라운드당 각자 5수로 제한한 뒤 판세 점수로 승패를 가른다. 패자는 HP가 줄고 HP 0이면 탈락하며, 제단은 공용 캐러셀로 확장한다. 장비 룬도 이 단계에서 검토한다

**아직 확인하지 못한 것**: 선후공 승률, 캐릭터·특성 승률, 긴장도 가중치, 증강 가치 환산은 모두 시뮬레이션과 플레이테스트 전의 초기값이다.

**열린 질문**

- 라운드당 1수가 모바일에서 느슨하다면 2수로 늘릴지 (봇 대전 단계에서 판단)
- 13×13과 15×15 중 스킬과 더 잘 맞는 쪽은 어디인지
- 준비 페이즈 20초가 모바일 한 손 조작에 충분한지
- 추격 보너스가 일부러 지는 플레이를 유도하지 않는지 (4점 격차 +2 상한이 적절한지)
- 시간 정지처럼 상대 행동을 막는 효과가 불쾌감을 주지 않는지
- 수익 모델: 승패에 영향을 주지 않는 연출·석혼 스킨 중심으로 갈지
- 제목과 세계관 이름 확정 (가칭 천원)
