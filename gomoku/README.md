# 천원 天元 · 오목 택틱스

`v1.0 최종 기획안.md`를 바탕으로 만든 서버 권위형 1:1 웹 게임입니다. 다른 게임들의 방 코드 입장, 준비 대기실, 개별 세션 복구 구조를 참고했습니다. 이 폴더에서 독립적으로 개발·실행할 수 있으며, 저장소의 Render 통합 Docker 배포와 게임 선택 화면에도 연결되어 있습니다.

## 개발 실행

Node.js 22 이상을 사용합니다.

```bash
cd gomoku
npm ci
npm run dev
```

- 게임: **http://localhost:5180/gomoku/**
- 게임 서버: `http://localhost:3011`
- 상태 확인: `http://localhost:3011/health`
- WebSocket / Socket.IO 경로: `/api/gomoku/socket`

이 작업 환경에는 의존성이 설치되어 있으므로 `npm run dev`로 시작할 수 있습니다. 기본 포트는 다른 게임과 겹치지 않습니다. 웹과 서버 사이의 연결은 Vite 프록시를 사용하므로 `VITE_SOCKET_URL` 설정이 필요하지 않습니다.

휴대폰은 같은 Wi-Fi에서 `http://개발PC의LAN주소:5180/gomoku/`에 접속하세요. 두 브라우저 또는 서로 다른 기기로 방 코드를 공유하면 됩니다. 동일 브라우저의 두 탭은 같은 좌석을 복구하므로 2인 테스트에는 시크릿 창 또는 별도 브라우저를 사용하세요.

## 플레이 흐름

1. 이름을 입력하고 방을 만듭니다. 공개 대기실을 켜면 시작 화면의 목록에 표시됩니다.
2. 초대 링크나 6자리 코드로 상대가 참가합니다. 혼자 연습할 때는 **사범과 연습** 또는 대기실의 **AI 사범 초대**를 사용합니다.
3. 두 사람 모두 준비하고 방장이 시작합니다. 서버가 금화를 던져 흑석 선공과 백석 후공을 결정합니다.
4. 준비 시간에 구매·판매·리롤·경험치 구매를 합니다. 양쪽 정비 완료 시 20초를 기다리지 않고 진행합니다.
5. 벤치의 석혼을 선택하거나 무료 기본 돌을 사용합니다. 교차점 탭 → 미리보기 → **착수 확정** 순서입니다.
6. 보드의 아군 액티브 석혼을 탭해 스킬과 대상을 선택합니다. 밀기는 상대 돌과 도착 칸, 교환은 아군 돌과 상대 돌을 차례로 지정합니다.
7. 착수 후 선택적으로 스킬을 쓰고 **턴 마치기**를 누릅니다. 스킬을 먼저 써도 됩니다. 시간 초과 시 자동 대리 착수하며 누적 3회면 기권됩니다.
8. R3·7·11 증강, R4·8·12 제단을 선택하고 5목 이상을 완성합니다. 결과에서는 보드 복기와 공개 기록 JSON 저장, 같은 방에서 재대국을 할 수 있습니다.

단축키: `1~5` 구매, `D` 리롤, `F` 경험치, `Space` 착수/스킬 확정 또는 턴 종료, `Q/W` 선택한 석혼의 스킬, `Esc` 취소. 채팅과 설정 입력 중에는 대국 단축키를 처리하지 않습니다.

## 구현 범위

- 시작 화면, 공개 방 목록, 코드·링크 초대, 2인 대기실, 준비 상태, 방장 권한, 채팅, AI 좌석
- 13×13 보드, 금수 없는 장목 승리, 무료 기본 돌, 서버 타이머, 대리 착수, 기권·무승부·재대국
- 선후공 골드·마나 보정, 단계별 XP/상점 확률, 공유 풀, 5칸 상점, 9칸 벤치, ★ 합성, 구매 총액 판매, 이자·추격·상단 수입 상한·12회 리롤 보호
- 기획안의 석혼 24종, 특성 8종, 증강 12종과 제단 1-2-1 드래프트
- 방패·봉인·제거·밀기·교환·토큰·추가 착수·시간 정지 및 예고 규칙 5개 조항
- 본인 상점/벤치/증강 후보만 전송하는 개별 view와 추측 불가능한 재접속 토큰
- 모바일 세로 대응, 착수 확인, 위협 라인과 승부처 표시, 상태 문양, 석혼 도감, 첫 대국 안내
- 연출 강도 3단계, OS 모션 감소, 색약 보조, 효과음·배경음 볼륨, 지원 기기 햅틱
- 실제 보드 변경을 기록하는 복기와 공개 기록 내보내기
- PWA 매니페스트, 서비스 워커, 오프라인 안내. 홈 화면 설치는 HTTPS 또는 localhost에서 지원됩니다. 대국에는 서버 연결이 필요합니다.

## 기획안을 구체화한 부분과 현재 한계

기획에 대상 선택 방식이 없는 배치 효과(수호병 방패·연막 토큰·칼날 방패 파괴)는 조건을 만족하는 대상으로 자동 적용합니다. ★3은 적용 가능한 스킬의 인접 대상 추가 또는 범위 확장으로 처리합니다. 승급 증강의 대상을 고르지 않으면 적격 벤치 석혼 중 첫 대상을 고릅니다. 제단은 빈 벤치도 합성 가능성도 없으면 선택을 건너뜁니다. 증강 시간 초과는 사용 가능한 후보를 자동 선택합니다.

현재 AI는 위협 차단과 연결 점수에 기반한 휴리스틱 사범입니다. MCTS와 실력 3단계, 첫 판 R1~R6 강제 시나리오는 아직 구현하지 않았습니다. 첫 대국 안내는 실제 봇 대국에 단계별 설명을 표시합니다.

렌더링은 React·SVG·CSS를 사용합니다. 착수, 상태 문양, 위협 라인, 스킬 배너, 막과 라운드 표시는 구현되어 있으며, PixiJS/GSAP 기반 영웅별 컷신·자동 편집 영상과 4스템 국악 오케스트라 음원은 포함하지 않습니다. 오디오는 Web Audio로 합성합니다. 공유 기록은 JSON이며 완성 영상 내보내기는 제공하지 않습니다.

네이티브 iOS/Android 패키징은 포함하지 않습니다. 현재 앱 형태는 PWA입니다. 계정·랭킹·시즌·토너먼트·운영 텔레메트리 수집 서버도 범위에 포함하지 않았습니다. 밸런스는 기획안의 초기 수치를 유지하며, 출시 목표 달성을 주장하지 않습니다.

## 검증

```bash
npm test
npm run build
# 먼저 npm run dev를 실행한 별도 터미널에서:
npm run test:browser
# Chrome이 없는 환경:
npx playwright install chromium
npm run test:browser
# 모바일 화면 검증 (서버는 테스트가 자동 실행):
npm run test:mobile
# Safari 계열 엔진 검증 (최초 1회 npx playwright install webkit):
MOBILE_BROWSER=webkit npm run test:mobile
# 시드 기반 자가대국:
npm run simulate -- --games=100 --mode=tactics
npm run simulate -- --games=10000 --mode=plain
```

룰·서버 테스트는 예고 규칙 5개 조항, 승리/장목/경계, 모든 스킬 프리미티브, 보호·봉인·방패·시간 정지, 12종 증강, 제단, 경제·풀 보존·합성, 상점 확률(레벨마다 10만 회), 특성 도달과 가치/마나 상한을 검사합니다. 실제 Socket.IO 클라이언트로 인증·방장 권한·차례·상대 정보 은닉·재접속·재대국도 검증합니다.

브라우저 검증은 서로 다른 두 세션에서 생성/참가, 구매, 벤치 비공개, 착수 동기화, 새로고침 복구, 증강, 제단, 기권, 재대국과 390px 모바일 화면의 가로 넘침을 검사합니다. 스크린샷은 `artifacts/`에 생성합니다. 모바일 전용 검증은 320·360·390·430px 세로 화면과 667px 가로 화면, 768px 태블릿에서 시작·대기실·준비·착수·스킬·증강·제단·결과·설정의 겹침과 보드 크기를 검사합니다. 긴 닉네임, 꽉 찬 벤치와 터치/길게 누르기도 확인하며, 결과 이미지는 `artifacts/mobile-chromium/`, `artifacts/mobile-webkit/`에 저장됩니다.

초기 전략 봇 100판 결과는 `tests/baselines/tactics-100.json`에 있습니다. 오류 없이 종료됐으나 **선공 승률 72%, 평균 21.38라운드, 스킬 사용 비율 약 74.6%**로 기획안의 목표와 차이가 있습니다. 상대 알고리즘이 동일한 휴리스틱이고 표본이 작으므로 사람의 승률로 해석해서는 안 됩니다. 기본 돌 무작위 대국 1,000판도 오류 없이 종료됐으며 결과는 `tests/baselines/plain-1000.json`에 기록했습니다. 현재 수치는 플레이테스트와 밸런스 조정이 필요한 상태입니다.

## 프로덕션 실행

```bash
npm ci
npm run build
PORT=3011 npm start
# http://localhost:3011/gomoku/
```

Express가 웹 빌드와 Socket.IO를 함께 제공합니다. reverse proxy를 사용한다면 `/gomoku/`와 `/api/gomoku/socket/`을 같은 인스턴스의 `3011` 포트에 전달하고 WebSocket Upgrade를 허용하세요. 헬스 체크는 `/api/gomoku/health`를 사용할 수 있습니다. 저장소 루트에서 `npm run build:render`를 실행하면 `apps/web/dist/gomoku/`에 통합 웹 빌드가 생성됩니다. 루트 및 `apps/server/Dockerfile`을 사용하는 Render 배포에서는 게임 선택 화면에 천원이 표시되고, 공통 시작 스크립트와 Nginx가 웹·소켓 경로를 연결합니다.

이 폴더만 컨텍스트로 Docker 실행도 가능합니다.

```bash
cd gomoku
docker compose up --build
# http://localhost:3011/gomoku/
```

방과 게임 상태는 **단일 프로세스 메모리**에 보관합니다. 연결이 끊겨도 동일 서버가 살아 있으면 같은 브라우저에서 복구합니다. 서버 재시작·재배포 후에는 복구되지 않으며, 다중 인스턴스로 운영하려면 공유 저장소와 세션 라우팅을 추가해야 합니다. 모두 연결이 끊긴 방은 마지막 상태 변경 후 30분이 지나면 정리됩니다. 재접속 토큰은 브라우저 localStorage에 보관하며 채팅·방 목록·다른 플레이어 view에는 전송하지 않습니다.

## 소스 구조

```text
shared/data.ts       석혼·특성·증강·경제 데이터
shared/types.ts      내부 상태, 공개 view, intent, 복기 타입
shared/engine.ts     시드 RNG, 순수 reducer, 판정, 경제·효과·타이머
server/app.ts        방·세션·서버 권한, Socket.IO, 봇 스케줄러
server/index.ts      서버 실행과 프로덕션 정적 파일 제공
src/main.tsx         시작/대기실/대국/결과/설정/도감/복기
src/styles.css       월광 신전 테마와 반응형 화면
src/audio.ts         합성 효과음과 배경음
public/              PWA·아이콘·오프라인 안내
tests/              룰·소켓·브라우저 검증과 자가대국
```
