# 천원 天元 · 오목 택틱스

오목의 수읽기와 보호·밀기·봉인을 결합한 서버 권위형 1:1 웹 게임입니다. 기본 대국은 `focused` 전술 규칙을 사용합니다. 기존 성장 규칙은 엔진의 `classic`으로 보존하며 기본 대국에는 적용하지 않습니다. 다른 게임들의 방 코드 입장, 준비 대기실, 개별 세션 복구 구조를 참고했습니다. 이 폴더에서 독립적으로 개발·실행할 수 있으며, 저장소의 Render 통합 Docker 배포와 게임 선택 화면에도 연결되어 있습니다.

## 개발 실행

Node.js 22 이상을 사용합니다.

```bash
cd gomoku
npm ci
npm run dev
```

- 게임: **http://localhost:5180/gomoku/**
- 게임 서버: `http://localhost:3011`
- 상태 확인: `http://localhost:3011/health`
- WebSocket / Socket.IO 경로: `/api/gomoku/socket`

이 작업 환경에는 의존성이 설치되어 있으므로 `npm run dev`로 시작할 수 있습니다. 기본 포트는 다른 게임과 겹치지 않습니다. 웹과 서버 사이의 연결은 Vite 프록시를 사용하므로 `VITE_SOCKET_URL` 설정이 필요하지 않습니다.

휴대폰은 같은 Wi-Fi에서 `http://개발PC의LAN주소:5180/gomoku/`에 접속하세요. 두 브라우저 또는 서로 다른 기기로 방 코드를 공유하면 됩니다. 동일 브라우저의 두 탭은 같은 좌석을 복구하므로 2인 테스트에는 시크릿 창 또는 별도 브라우저를 사용하세요.

## 플레이 흐름

1. 방을 만들고 친구를 초대하거나 AI 사범과 시작합니다.
2. 양쪽 모두 보호·밀기·봉인 석혼 하나씩, 3G와 마나 4로 시작합니다. 첫 보급에서 추가 구매는 선택입니다.
3. 무료 기본 돌 또는 벤치 석혼을 고르고 빈 교차점 → 미리보기 → 착수 확정으로 돌 하나를 놓습니다. 모바일에서는 화살표로 한 칸씩 조정할 수 있습니다.
4. 보호는 배치 즉시 인접한 아군 돌 하나에 방패를 줍니다. 밀기는 석혼 주변 2칸 안의 적 돌을 인접한 빈칸으로 옮기고, 봉인은 주변 3칸 안의 적 돌을 잠시 연결에서 제외합니다. 석혼 배치 미리보기에서 사거리를 표시하므로, 놓을 위치로 다음 전술을 준비할 수 있습니다. 유효한 대상과 바뀔 돌, 공격·수비 결과를 확정 전에 표시합니다.
5. 착수와 선택적 스킬 1회를 원하는 순서로 사용한 뒤 항상 **턴 마치기**를 누릅니다. 턴 종료 마나는 +2입니다. 스킬은 생략할 수 있습니다.
6. R1·5·9…에만 보급이 열립니다. 첫 보급 이후 양쪽에 4G를 지급하고 같은 세 종류를 제시합니다. 각 슬롯에서 한 번 구매할 수 있고 벤치는 6칸입니다. 이자·경험치·합성·특성·증강·제단은 없습니다.
7. 먼저 다섯 돌 이상을 연결하면 승리합니다. 기본 보급은 25초, 턴은 45초입니다. 시간 초과 시 대리 착수하며 누적 3회면 패배합니다.

방금 둔 돌은 다음 상대 턴까지 스킬로부터 보호됩니다. 방패가 있으면 밀기·봉인은 방패만 파괴합니다. 스킬로 새로 만든 승부처는 상대 대응 후 사용할 수 있습니다. 미리보기는 실제 reducer를 사용하고 상대의 비공개 벤치·상점은 사용하지 않습니다.

모바일은 하단에서 **놓을 돌 / 스킬**을 전환합니다. 보드는 기기 너비를 사용하며 작은 화면이나 선택 안내가 길어지는 상황에서는 보드 영역을 스크롤할 수 있습니다. 가로 화면에서는 보드와 조작부를 좌우로 나눕니다. 데스크톱은 보드 옆에 조작부를 표시합니다.

## 검증

```bash
npm test                 # 기존 규칙 및 전술 규칙, 미리보기, 실제 Socket.IO 세션 검증
npm run build           # 타입 검사와 웹/서버 빌드
npm run test:browser     # 임시 서버를 자동으로 띄워 전술 브라우저 흐름 검증
npm run test:mobile      # 같은 시나리오를 모바일/태블릿/데스크톱 크기로 검증
MOBILE_BROWSER=webkit npm run test:mobile
MOBILE_WIDTH=360 npm run test:tactics
```

브라우저 검증은 320·360·390·430px 세로, 667px 가로, 768px 태블릿과 1024px 데스크톱에서 보급 구매·배치·좌표 조정·명시적 턴 종료·길게 누르기·봉인과 밀기의 유효 대상·미리보기·결과를 검사합니다. 캡처는 `artifacts/tactical-chromium/`, `artifacts/tactical-webkit/`에 저장합니다.

기존 성장 규칙과 직접 연습 모델의 단위 테스트는 유지합니다. `test:practice`와 `simulate`는 기존 `classic` 규칙용이며 기본 전술 대국의 재미·밸런스 검증을 대신하지 않습니다. 기존 `tests/baselines/` 결과 역시 전술 규칙의 승률로 해석하면 안 됩니다.

현재 AI는 연결·승부처를 평가하는 휴리스틱입니다. 전술 모드에서는 이득이 있는 밀기·봉인을 평가하고 배치할 석혼을 고릅니다. 실제 사람 사이에서의 재미와 선후공 밸런스는 별도 플레이테스트가 필요합니다.

## 프로덕션 실행

```bash
npm ci
npm run build
PORT=3011 npm start
# http://localhost:3011/gomoku/
```

Express가 웹 빌드와 Socket.IO를 함께 제공합니다. reverse proxy를 사용한다면 `/gomoku/`와 `/api/gomoku/socket/`을 같은 인스턴스의 `3011` 포트에 전달하고 WebSocket Upgrade를 허용하세요. 헬스 체크는 `/api/gomoku/health`를 사용할 수 있습니다. 저장소 루트에서 `npm run build:render`를 실행하면 `apps/web/dist/gomoku/`에 통합 웹 빌드가 생성됩니다. 루트 및 `apps/server/Dockerfile`을 사용하는 Render 배포에서는 게임 선택 화면에 천원이 표시되고, 공통 시작 스크립트와 Nginx가 웹·소켓 경로를 연결합니다.

이 폴더만 컨텍스트로 Docker 실행도 가능합니다.

```bash
cd gomoku
docker compose up --build
# http://localhost:3011/gomoku/
```

방과 게임 상태는 **단일 프로세스 메모리**에 보관합니다. 연결이 끊겨도 동일 서버가 살아 있으면 같은 브라우저에서 복구합니다. 서버 재시작·재배포 후에는 복구되지 않으며, 다중 인스턴스로 운영하려면 공유 저장소와 세션 라우팅을 추가해야 합니다. 모두 연결이 끊긴 방은 마지막 상태 변경 후 30분이 지나면 정리됩니다. 재접속 토큰은 브라우저 localStorage에 보관하며 채팅·방 목록·다른 플레이어 view에는 전송하지 않습니다.

## 소스 구조

```text
shared/data.ts       석혼·전술 역할·기존 성장 규칙 데이터
shared/types.ts      내부 상태, 공개 view, intent, 복기 타입
shared/engine.ts     시드 RNG, 순수 reducer, 판정, 경제·효과·타이머
server/app.ts        방·세션·서버 권한, Socket.IO, 봇 스케줄러
server/index.ts      서버 실행과 프로덕션 정적 파일 제공
src/main.tsx         시작/대기실/대국/결과/설정/도감/복기
src/styles.css       기존 테마와 반응형 화면
src/tactics.css      전술 대국과 모바일 조작부
src/tactical-model.ts 실제 엔진 기반 비공개 정보 없는 행동 미리보기
src/audio.ts         합성 효과음과 배경음
public/              PWA·아이콘·오프라인 안내
tests/              룰·소켓·브라우저 검증과 자가대국
```
